认识与启动

认识 UGSci

面向油气工程、地下储气库和科学研究的智能协作工作台。

软件定位

UGSci 将自然语言任务、领域专家、可执行计算工具、专业仿真软件和成果展示组织在同一工作环境中。用户可以从一份测井文件、一组注采数据或一个研究问题开始，逐步完成输入检查、计算分析、多专家复核和成果整理。软件适用于油藏工程师、储气库研究人员、测井解释人员、科研工作者及团队管理员。

桌面产品使用 UGSci Desktop 品牌；技术底座沿用 QwenPaw 的本地部署、模型配置、智能体工作区、记忆、技能、工具、安全和自动化体系。UGSci 领域组件提供行业界面与计算功能，UGSci Research 提供可选科研模式。命令行、目录名及部分协议仍保留 qwenpaw 字样，这是兼容入口。

UGSci 的领域能力

油气工程：LAS 测井读取与质量检查、Arps 递减拟合和预测、储量估算、油气藏物质平衡、黑油 PVT 筛选、Vogel IPR、节点分析及质量守恒检查。

地下储气库：账面库存、分层有效库存、综合库存评价、库容筛选、井组配注配产候选方案，以及带约束和权重的方案排序与 Pareto 比较。

可信计算：记录输入指纹、算法与版本，展示公式代入、变换和有效性判断；对支持的公式计算使用签名重放令牌进行复算。

协作与表达：六种专家团模式、固定协作工作流、仿真任务跟踪、油气三维与测井可视化、GenUI 交互成果以及可选的文献和科研工作流。

能力生效条件

技能是操作方法，工具才是实际执行入口。共享技能库里有技能，不代表当前专家已安装或已启用。外部求解器需要有效安装路径、许可证、输入文件和配套依赖；科研检索需要相应网络与工具连接。

数据和工作区可以保存在本机。使用云端模型、外部 MCP 或联网检索时，相关输入仍可能发送到所配置的服务；本地部署不自动等于全程离线。计算建议需要业务人员复核，软件不会因为得到数值就完成工程审批。

首次使用与安装

从启动、模型配置到完成第一次有结果可检查的任务。

安装与运行环境

一般用户优先使用团队提供的 UGSci Desktop 安装包。Windows、macOS 或 Linux 的具体可用版本以交付安装包为准。本手册的 Windows 操作示例建议使用现代 64 位系统、可用的本地写入目录及更新的浏览器；这些是部署建议，不是已经完成的全平台兼容认证。

源码运行要求 Python 3.11 至 3.13；前端构建还需按项目要求准备 Node.js。运行大型三维模型、并行专家或外部数值模拟时，内存、显卡、CPU、磁盘与许可证要求取决于模型规模和专业软件。首次验证可从小型文件和只读任务开始。

桌面版启动

  1. 运行团队提供的安装程序，按向导完成安装，并确认安装包来源。双击 UGSci Desktop，等待后端服务和窗口就绪。
  2. 打开设置中的模型页面，填写所用模型服务的地址、密钥和模型名称，或连接已部署的本地模型服务。保存后将模型指定给当前专家。
  3. 在左侧选择当前专家，发送“只介绍你的职责，不运行任何工具”。出现有效回复，说明模型调用链路已连通。
  4. 查看专家·协作、工具·技能及油气可视化入口。若前两个入口未显示，切换侧栏的极简模式，并确认 UGSci 组件已加载。

源码版启动

开发者应从本项目目录安装，避免把公开仓库的原版安装包当成包含全部 UGSci 定制内容的交付包。先建立虚拟环境，再安装本项目依赖、初始化运行目录并启动服务。以下为 Windows PowerShell 示例，C:\UGSci\source 需要替换成实际项目目录；已有配置时不要直接使用强制覆盖初始化。 

cd C:\UGSci\source
python -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install -e .
qwenpaw init --defaults
qwenpaw app

模型与工作区基础

明确当前专家使用哪个模型、能访问哪些数据、会调用哪些能力。

配置模型

  1. 进入设置中的模型管理，选择已有提供商或创建自定义提供商，填写实际服务地址与认证信息。密钥保存在配置中，不写入提问模板或成果文件。
  2. 选定可用模型并保存；返回专家配置，确认当前专家的活动模型。不同专家可以使用不同模型。
  3. 先发送简短文本问题，再测试需要的图片或长文档输入。只有服务明确支持相应输入类型时才使用该能力。

如何选择模型

任务 优先检查 使用建议

复杂方法推理与复核 推理能力与工具调用 保留方法和验收标准

管理工作区

每个专家对应一个智能体及其配置和工作区。模型、提示词、技能、MCP、记忆和对话历史随所选专家变化。切换专家后先检查当前名称，避免将文件或能力分配给错误角色。

建议每个业务项目建立 inputs、working、results 三个目录。inputs 存原始数据，working 存中间计算副本，results 存交付文件。目录名称可以自定，但应在任务中写明原始文件只读、输出路径和覆盖规则。

上传文件或提供路径前，确认文件已落到当前专家可访问的位置。聊天里出现文件名不等于引擎能直接访问该文件。将多个关联文件保持在同一项目目录，可减少伴随文件缺失。

结果保存与切换

  1. 完成任务后要求输出实际文件路径、文件格式、输入数据来源和计算方法。
  2. 在文件或工作区面板中打开产物，核对内容和大小，再备份整个项目。
  3. 切换专家复核时明确指定已保存的结果文件及其路径；不要默认两个专家自动共享全部文件和记忆。

生成交互成果

GenUI 通过已注册的组件目录生成结构化交互界面，并可以用补丁增量更新。适合展示参数表、图表、表单、状态和分析结果。可用组件与交互取决于目录和工具契约，不是任意网页代码都能直接运行。

用户应先说明真实数据来源、显示字段、单位、可编辑项及提交影响。表单填写不等于已执行计算或已写入文件；提交之后需要检查反馈和实际产物。

查看文件和成果

  1. 在对话或工作区打开生成的成果，核对图表轴、单位、数值、记录数量和输入参数。
  2. Office 文件优先使用后端转换预览；转换不可用时可能回退到前端 OOXML 解析或下载。DOCX、XLSX、PPTX 的复杂版式可能与原软件有差异。
  3. 文件预览用于阅读检查；需要编辑或验证正式版式时使用相应文档软件。报告必须包含真实已生成的文件路径。

导出交互界面

GenUI 支持 PNG 截图、HTML 导出及打印/保存 PDF。HTML 导出保留可支持的界面和本地表单状态，但离线页面不会向 UGSci 后端发送消息或提交数据。

PNG 导出适合静态截图；打印 PDF 需要浏览器允许打印窗口。导出前确认所有图片已加载，导出后重新打开检查文字、图表和媒体。

领域技能覆盖油气基础、勘探、钻完井、油藏与生产、测井、地震数据、数据分析、科学计算和工程协作。科研技能覆盖文献检索、写作、统计、可视化、数据库和研究方法，按实际任务选择。

使用市场与应用

  1. 打开市场，切换到 UGSci 分区。旧 /ugsci-market 路由会转向 /market?tab=ugsci；原有截图可能显示较早的独立市场布局。
  2. 根据任务搜索技能、MCP 或专家模板。查看来源、依赖、访问权限和安装目标。
  3. 安装后检查当前专家配置；第三方资源的安装落点和启用步骤以具体资源类型为准，不能假设都自动启用。
  4. 应用入口用于打开已安装的完整工作台；应用可能需要独立数据目录或外部账号，应按该应用说明配置。

能力验证

如果技能已显示但工具无法执行，检查依赖、工具启用状态和审批策略。不要通过重复安装技能替代修复缺失运行环境。移除技能或工具前核对是否有正在运行的任务依赖它。

角色派发与失败处理

OMP 表示多专家编排工作流。专家团可以按角色派发子任务，部分角色由控制专家在运行时生成；是否需要固定实例取决于团队绑定设置与实际运行权限，不能沿用旧手册“缺少同名专家就一定无法运行”的判断。

固定协作工作流

把重复任务变成可编辑、可运行、可复核的流程。

专家团与固定流程的区别

专家团适合开放讨论和多角色协作；协作工作流适合明确规定输入、步骤、依赖和交付物的重复业务。固定流程仍需要可执行的专家实例和工具配置，保存草稿不等于完成运行验证。

生成与编辑流程

  1. 在专家·协作中切换协作工作流，输入业务目标、文件字段、角色、执行顺序及验收要求。
  2. 点击生成可编辑草稿或使用流程模板创建草稿。检查每个节点的专家绑定、输入输出和依赖。
  3. 当前固定流程的专家节点优先使用已经创建并验证的固定实例。该页面列出的优先实例、模板派生和按健康/成本动态路由策略属于规划项，不应当作固定工作流已实现功能。
  4. 保存草稿后以小型项目运行，检查节点状态、事件、失败原因及最终文件。通过测试后再复制到正式项目。

月度报告流程描述

目标：生成月度单井递减分析报告。
输入：production.csv，包含 date、oil_rate，注明日期与产量单位。
步骤：数据检查 → 油藏工程计算 → 独立复算 → 报告整理。
各节点使用已验证的固定专家。
验收：输入只读，输出到 results；包含参数表、图表、预测边界与未解决问题。

更新流程

改变输入字段、计算方法或专家配置后，应重新试运行。为正式项目保存流程版本、关键参数和输出清单，避免无法解释两次运行结果差异。

出现节点失败时从日志确定失败阶段，先修正该节点依赖，再决定重试。对会产生文件或外部计算的节点，应核对之前是否已经成功执行。

工具·技能与引擎

本地引擎与 MCP 接入

区分软件定义、检测结果、依赖可用和真实计算成功。

检查引擎

  1. 打开工具·技能的引擎视图，按仿真软件、领域计算和运行服务查看配置。
  2. 点击自动检测，读取软件名称、版本、路径与状态。检测依赖常见安装路径和可执行文件线索。
  3. 非标准安装位置使用添加引擎或配置入口补充实际路径、分类和调用信息。保存后重新检测。
  4. 运行前单独检查许可证、工作目录、模型输入、配套文件和读写权限；先做只读检查或小模型测试。

支持条件

项目含 CMG、Eclipse、Intersect、tNavigator、COMSOL 等调用适配器，也维护 Petrel、Techlog、PIPESIM、OFM 等软件检测定义。列在检测清单中的软件不一定具有可直接执行的 UGSci 适配器。

COMSOL 批处理依赖实际软件与许可证，结果读取可能使用模型关联导出或 CSV。容器环境下无法自动访问宿主机所有安装目录和许可证；需要单独配置可访问的运行方式。

领域计算引擎提供确定性工程计算及可选科学计算库。SymPy、SciPy、PyMC 等适配器依赖相应库；NeqSim 还需要其运行环境和 Driver 连接就绪。软件应对依赖缺失返回明确错误，不使用虚构计算结果替代。

接入 MCP

  1. 在工具视图的 MCP 接入中新增服务，按服务说明选择 stdio、SSE 或 Streamable HTTP 传输。
  2. 本地 stdio 服务填写真实启动命令与参数，远程服务填写 URL 和必要认证。保存后检查连接与工具列表。
  3. 仅向需要的专家开放服务和工具，按服务要求完成 OAuth 或访问策略设置。
  4. 先执行不会修改外部数据的查询，核对返回结果及连接日志；通过后再用于正式任务。

ACP 运行服务

运行服务分类可嵌入主平台的 ACP 配置，用于连接外部 Agent runner。按当前界面创建、编辑或选择 runner，并进行配置校验；它与本地仿真求解器是不同类型的运行能力。

地下储气库库存与库容评价

统一层系、状态、压力和计量口径，区分账面库存与有效库存。

准备评价输入

储气库评价应先确定评价周期、注气末状态、后续采气评价状态和层系划分。所有气量采用一致的标准状态与体积单位；同一层系的两个压力状态必须采用同一种明确声明的压力口径。

有效库存支持 absolute、apparent_formation 和 report_defined 三种压力口径声明。报告使用视地层压力时，应按该报告口径输入；系统不应悄悄改称绝压或混用口径。Z 因子、采气量和压力必须对应同一层系与采气段。

指标 主要输入 解释

  1. 选择已启用储气库评价工具的专家，提交各层采气量、注气末压力/Z、评价压力/Z，以及评价周期和状态标识。
  2. 提供账面库存，或提供期初库存和同期注采量；按工具契约选择一种账面库存输入方式。补充设计库容、垫底气和冲峰指标所需数据。

  4. 查看逐层结果、汇总指标、告警、方法、单位、输入指纹和待复核状态；保存结果后安排独立复核。

公式与稳定性

账面库存按 Gr = G0 + 累计注气量 − 累计采气量计算。分层有效库存按 Grm = Qp × (Pin/Zin) ÷ [(Pin/Zin) − (P/Z)] 计算，然后逐层求和。不能以账面库存减垫底气或全库平均压力替代分层有效库存公式。

需要 Qp > 0、正且有限的压力与 Z 因子，并满足 Pin/Zin > P/Z。p/Z 差值接近零时结果不稳定，工具按数值和工程阈值告警或拒绝；Grm/Qp 大于 20 时告警，大于 100 时拒绝。这个比值是撤采比例倒数的筛选代理，不是完整误差传播倍数。

库容筛选

库容评价工具按分层连通孔隙体积、最大/最小运行压力、对应 Z 因子、地层温度和标准状态筛选总库容、垫底气与工作气量。应先明确压力上下限与孔隙体积来源。

库存和库容工具固定输出待复核计算建议。工具不负责写入已批准状态；正式设计需结合地质、PVT、数值模拟和井筒能力复核。

储气库配注 配产和方案比较

在明确的约束与候选集合中生成可解释的建议。

井组配注与配产

配注和配产工具按可用井的最小/最大运行量及优先级权重分配目标量。先满足最小运行量，再按权重分配剩余需求，直到达到单井上限。不可用井不参与分配。

输入包括井或井组名称、最大能力、可选最小能力、权重和可用状态，以及本次目标量和统一单位。权重是分配偏好，不代表自动学习到的井组效益或安全等级。

操作步骤

  1. 整理井组能力表，排除检修或不可用井，核对上下限和目标量采用同一日率单位。
  2. 选择配注或配产工具，声明目标量和权重来源，提交结构化参数。
  3. 检查总分配量、未满足量或超供量、单井利用率和 feasible 状态。目标超出能力时可能返回可执行部分和不可行标识；require_feasible 可要求直接拒绝不可行输入。
  4. 将候选方案与井筒、管网和数模约束联合复核后，另行形成业务计划。

多方案比较

方案比较入口接受候选方案的标量指标、目标方向与权重、以及 <=、>= 或 == 约束。系统先筛除不满足约束的候选，再用本次集合的目标范围归一化并计算加权排序，同时识别 Pareto 非支配前沿。

可行方案少于三个、没有可行方案或指标缺失时，应检查告警。排名是本次输入集合内的相对比较；改变候选集合或权重可能改变排名，不是连续空间中的全局最优证明。

适用边界

上述工具用于早期工程筛选，不自动推断井间压力干扰、管网水力、瞬态或非均质性，也不会自动批准或写回生产模型。正式计划应结合耦合数模、敏感性和不确定性分析。

用明确输入 输出和判断标准验证一次完整任务。

示例一 测井质量检查

任务目标是整理 well01.las 的曲线和异常，不直接做储层定级。输入准备 LAS 文件与曲线单位说明。先选择测井分析师，确认读取与校验工具，运行只读检查；如果需要规范化导出，另存到 results。

验收：实际读入文件，列出深度范围、曲线单位、缺失值与异常段；保留检查报告；导出文件再次可读。没有岩心、地层标定等依据时，不把初步曲线检查写成正式解释结论。

示例二 储气库分层库存评价

准备每层同一采气段的采气量、注气末与评价状态压力/Z，明确压力口径、标准体积单位及周期标识。准备账面库存或同期注采账本、设计基准与需要的垫底气参数。

依次完成输入核查、综合库存计算和独立复核。验收：层系单独计算后汇总，账面库存与有效库存分开列示；保留稳定性告警、方法、输入指纹和待复核状态；不得在缺少业务审批时标注已批准。

示例三 方案排序与数模复核

为多个候选注采方案提供可比较指标，注明最大化/最小化方向、权重和约束。先用方案工具筛选可行集合，查看得分和 Pareto 标记，再选有代表性的候选送入外部数模。

验收：每个候选约束结果可见，权重与指标范围可解释，排名范围限定于本次集合；保存数模输入、许可证/版本信息和日志；数模结果与筛选建议之间的差异得到说明。

示例四 科研综述与交互报告

启用科研组件，定义检索主题和纳入标准，保存真实文献来源并区分摘要与全文。建立方法比较表，对所选计算保留参数与复算信息，再将实际数据整理为交互报告。

验收：每条引文可以追溯；图表与数据一致；HTML/PNG 导出可打开；离线 HTML 不向平台提交任务；不把模式开关启用等同于完成检索或研究。

自动化 记忆和备份

用明确的时间和输出规则安排重复任务，保留可恢复的项目资料。

定时任务与心跳

定时任务按配置的时间或周期执行特定指令；心跳按间隔执行自检提示，是否通知及投递到哪个频道由配置决定。两者都需要运行服务持续可用，以及执行专家、模型和工具配置有效。

自动化适合资料更新、月度汇总或状态查询。涉及外部发送、文件改写和昂贵计算时，应先在一次性任务中验证输入输出和权限，再转为定时执行。

配置重复任务

  1. 打开定时任务，填写任务名称、执行专家、时间规则、明确时区和任务指令。
  2. 指令写明输入路径、输出目录、完成条件、失败处理以及哪些状态需要通知；不要将密钥写进指令。
  3. 保存后检查下一次执行时间，先做一次手动测试，再查看运行记录与实际文件。
  4. 暂停或删除不再需要的任务；更改数据目录或专家配置后重新测试。

频道与记忆

主平台提供多频道接入、记忆和上下文管理。接入钉钉、飞书等服务时，需要对应账号权限与频道配置。发送到外部频道之前明确收件范围和可外发数据。

记忆用于长期偏好和上下文，不代替项目原始数据、计算参数和正式成果库。切换专家时核对实际工作区；使用压缩或记忆后，必要时重新提供关键文件和约束。

备份与恢复

  1. 在维护窗口暂停正式任务，记录底座、组件和外部引擎版本。
  2. 按主平台备份功能导出需要的配置和工作区，另行保存关键输入、输出、流程和引擎配置。
  3. 恢复到独立环境后，检查模型、MCP、专家团、技能和文件路径；重新配置密钥和许可证等机器相关信息。
  4. 用小型只读任务和一项确定性计算验证恢复结果，再恢复正式调度。

运行安全与故障排查

从输入 模型 工具 运行环境和成果逐层定位问题。

日常操作要求

执行前看清当前专家、输入文件、输出目录和工具影响。原始数据保留副本；删除、覆盖、外部发送和正式仿真按团队规则确认。审批模式、文件访问控制和技能扫描是辅助防护，需要与实际权限配置一起使用。

导出报告时检查敏感字段、服务密钥和内部路径。外部资源和技能安装前阅读来源及权限说明；本地模型离线可用仍以全部依赖均在本地为前提。

科研工作流（历史版本）

在可选科研组件中组织问题 文献 方法和成果。

历史版本参考：当前组件已取消独立科研模式与设置入口；请使用实际可见的应用与成果面板。

启用科研模式

  1. 确认 UGSci Research 组件已启用，在当前专家的聊天工具栏点击研究模式开关。
  2. 打开研究设置，选择通用、物理、生物或机器学习领域，并核对科研相关技能、模型和检索工具。
  3. 打开研究面板，在图表、表格、代码、测井等分类中查看实际产生的成果。模式配置随当前专家变化。

科研任务流程

先定义研究问题和范围，再安排资料检索、文献阅读、方法设计、数据分析与成果整理。研究模式提供工作流提示和成果入口，不会自动取得所有论文全文或数据库授权。

文献检索技能可能依赖外部数据库或联网服务。保存题名、作者、年份、DOI/链接及实际读取内容；区分检索摘要、已读全文和待验证引用，不编造参考文献。

分析与写作

  1. 要求专家先说明研究问题、方法假设、所需数据和可用软件；选择能处理当前数据的方法。
  2. 执行分析并保存脚本、参数、软件版本、随机配置与输入指纹等可用复算信息。
  3. 将图表和表格加入研究面板，核对单位、统计口径和文献来源。
  4. 让独立专家检查证据与方法，再形成论文、报告或演示文稿；输出格式取决于已安装技能和依赖。

文献综述提问

整理方法对照表和证据缺口，不编造来源。
