# 后续发布的更新兼容保护

目标是让当前软件持续具备跨版本升级、差量失败后的全量恢复、用户数据保留及兼容检查能力；不以追溯安装过去十个桌面版本作为本次验收条件。

## 品牌资源随升级替换

- 原生宿主指纹同时包含规范源图 `icon.svg` 和提交的 `icon.ico`、`icon.icns`，Python 发布器与 Rust 宿主使用同一输入清单。Windows 或 macOS 图标内容变化会触发完整桌面升级，生成目录中的平台临时图标仍不参与指纹。
- Windows 覆盖安装显式重写开始菜单和桌面快捷方式的 `IconLocation`，安装、软件内升级和失败回滚均通知 Shell 刷新图标缓存。签名检查、完整性检查、健康确认和事务回滚继续执行。
- 控制台固定地址的公开资源使用 `Cache-Control: no-cache`，升级后浏览器重新校验 favicon、品牌图片等资源。内容哈希文件名的前端构建资源沿用原有路径。
- Chrome 解压扩展具有独立的安装副本和浏览器加载状态。插件升级后沿用 `extension_update_required` 检测，需要通过扩展更新入口复制新版资源并在 Chrome 中重新加载；不能以宿主插件已更新便认为浏览器中的图标已替换。


## 固定检查入口

```text
python scripts/verify_update_regressions.py
```

使用项目虚拟环境运行。该命令先确认必需测试文件与关键用例仍在，再执行更新器、客户端、发布产物、安装器交接、恢复和工作流回归。普通后端 CI 与发布的完整测试门禁先运行 `--check`，再由已有的跨平台完整单元测试执行这些用例，避免重复跑同一套测试。

新增的升级契约测试使用真实发布器生成临时签名更新包，经当前客户端的签名指针、清单、下载缓存、校验和原子安装流程消费。仅网络传输使用隔离测试响应，不连接线上、不改用户安装目录。覆盖：

- 匹配历史基线时应用差量；基线缺失、被修改或差量下载失败时使用签名全量包。
- 全量恢复仍然保留用户模型配置和工作区记录；全量包损坏时旧代码和用户数据保持可用。
- 升级成功后再次检查不会重复安装。
- 宿主协议、宿主指纹或最低版本不兼容时，阻止组件下载和激活，保留完整桌面更新路径。
- 现有回归继续验证备份失败阻止安装、中断恢复、健康确认前保留上一版本以及 Windows 安装交接约束。

## 实际发布产物门禁

`scripts/pack-tauri/verify_component_release.py` 由组件构建流程以及上传／提升流程分别执行，任何错误都会阻止后续步骤。检查：

1. 清单与所有实际 ZIP 的签名、SHA-256、长度、目标平台和兼容策略。
2. 每个组件必须提供全量恢复包，包内受管文件的完整清单与内容摘要必须吻合。
3. 差量包的来源／目标版本、基础／目标文件清单、增删改操作与实际文件内容必须一致；不得修改受保护数据。
4. 不安全路径、链接、重复文件、损坏 ZIP、缺失文件及指向发布目录以外的地址均拒绝发布。

构建器原有的逐个历史基线真实应用差量检查继续保留。历史不足或没有合适差量时允许全量更新，不将“必须存在十个旧版本”作为发布前提。

## 维护约束与边界

- 仓库自有应用和插件的宿主兼容上限统一为 `<3.0.0`，保留各自最低版本及 SDK／组件协议约束；源码与内置打包副本保持一致。`test_shipped_plugins_keep_major_version_compatibility_boundary` 验证后续 2.x 不因过窄上限被禁用，同时拒绝 3.0 正式版与预发行版。这是发布兼容声明，不替代对实际宿主接口的行为回归。

- UGSci 的 `visualization/data` 仅是本地可视化测试数据。插件清单、桌面／组件暂存、Python 包、源码包和 Docker 上下文均排除它；打包镜像同步也不得复制该目录。组件签名发布检查、桌面产物检查和插件市场打包检查遇到这类数据必须失败。`test_ugsci_release_data.py` 验证实际产物，以及无预置数据时的可视化导入能力。

- 最低兼容版本和组件协议维护在 `scripts/pack-tauri/component_compatibility.json`，不要跟随每次发布版本机械递增，也不能为了通过检查而降低协议门槛。
- Beta 9 的最低核心版本为 `2.2.2b9`：这次新增了对 UGSci 历史 `visualization/data` 用户导入目录的保留能力。旧核心不理解该受保护子目录，必须先完成桌面更新再激活插件，避免旧版全量替换丢失导入数据。该目录仍严格禁止进入任何发布包。
- 原生宿主、安装器、权限或签名策略改变时，保持主程序指纹与桌面完整更新路径。不得绕过签名或错误降级到不兼容组件。
- 前端的最新状态、版本说明、组件状态检查由 `console` 中的 `npm run test:fork-features` 保留。
- 校验失败必须修复包或代码；不得删除／跳过关键测试或在工作流添加容错放行。
- 宿主管理的 OfficeCLI 调用和构建期版本探测必须传入 `OFFICECLI_SKIP_UPDATE=1`，防止引擎后台自更新替换已审定的二进制。构建验证在执行版本探测后再次核对锁定 SHA-256；不能只相信版本标记文件。真实引擎测试同时核对执行前后的摘要，并保留 Word、Excel、PowerPoint、预览与宏内容保留回归。
- 当前改动增加自动防错措施，不代表任何系统都能承诺永远没有故障。完整桌面安装包仍由现有 Windows／macOS 构建和安装启动检查验收；本次本地验证不等于执行线上发布。

## 兼容声明与运行时升级回归

- 安装包内置目录作为插件更新源时，必须与本机官方目录中的精确路径、插件 ID、版本及宿主兼容性匹配；不能把任意本地目录加入外部下载白名单。更新沿用原生生命周期、活动任务确认、备份与失败回滚。插件启动失败只改变实际运行状态，必须保留用户的启用意图，允许兼容的新版本恢复运行；显式禁用不能被失败恢复改写。`test_plugins_router.py` 验证真实目录替换、失败插件恢复、忙碌确认和损坏候选回滚，`test_plugin_config_update.py` 验证启用与禁用意图，均纳入固定更新回归。

- 兼容范围、依赖或包内容改变时，必须发布高于原版本的新插件版本；不能在旧版本 URL 上覆盖 ZIP 或修改旧版目录元数据。当前修复将储量应用推进到 0.3.2，并同步其余兼容声明改变的插件版本与内置副本。真实 ZIP 回归核对版本递增及清单／元数据一致，Data 应用先由专用发布任务构建前端，再验证发布包。
- 预发行宿主遇到显式 Beta／RC 最低版本时，前后端均按实际预发行版本比较最低界限；稳定最低版本与独占上界继续按即将发布的稳定版本判断。
- 外部插件替换遇到 plugin_busy 必须返回 409 及原有结构化原因。仅用户确认后传 interrupt_tasks；忙碌拒绝发生在生命周期变更之前，不触发回滚重装。真实加载器回归保护取消前的旧版本和确认后的资源释放。
- 全仓库验收使用 pre-commit run --all-files、控制台 format:check 和固定前后端／更新器回归，不能仅以合并冲突文件的提交钩子结果代替。历史事务及数值算法保留局部复杂度例外，公共回调保留参数名；不修改全局检查门槛或删减测试。

## 插件、应用与组件更新的生命周期约束

- 手动替换的备份、当前版本复读与安装必须处于同一插件生命周期锁内。加载器负责回滚，路由不得再次强制安装旧备份；过期请求不得把已提交的新版本降级。同版本修复仍允许。
- 更新前必须检查宿主兼容性，包括启动时因禁用而没有加载记录的插件。显式禁用允许提交合法候选，但不得执行候选代码或改写用户启用意图。
- 持久提交之后的备份、标记及墓碑清理失败，返回已生效的新版本和明确的待清理诊断；提交之前失败继续走恢复流程。依赖升级确认必须保留结构化操作身份，由用户决定继续或取消。
- 启动恢复必须停止旧实例、孤立运行资源和后台准备任务。只有完整清理且已静止时才允许回滚目录；未停净或健康候选清理失败时保留恢复凭据，不强制移除运行记录。
- 待更新队列使用跨进程短锁和每次请求的独立身份。安装期间允许新请求入队，完成时只确认当前处理的那一代请求，不覆盖同组件的新请求。
- 原生宿主按每次启动的独立回执区分准备中、核心就绪、核心失败及主动更新重启。运行时上一版本的清理只能发生在核心就绪后；可选插件失败不等同核心启动失败。
- 应用列表合并安装文件与运行状态，保留失败、禁用、待启动应用及诊断。前端更新必须按应用身份撤销旧注册并加载新版，加载失败清理部分注册；加载、更新与卸载共用顺序控制，旧清单不得覆盖较新的用户操作。
- 受管应用服务只有通过健康检查且子进程存活才算就绪；进程退出后不得继续提供旧地址，再次启动必须回收旧进程资源。

行为回归由 `test_plugin_update_transactions.py`、`test_bundled_startup_safety.py`、`test_component_service.py`、`test_healthz.py`、`test_pawapp_listing.py`、`test_app_contract.py` 以及控制台的 `usePluginLoader.test.ts`、`AppCenter.updates.test.tsx`、`AppCard.test.tsx` 保护，并纳入固定检查清单。原生回执和旧健康接口兼容性同时由 Rust daemon 测试保护。

## 依赖层体积与内容稳定性

桌面锁必须满足当前核心、已选 extras、UGSci 读取器与离线工具链的全部直接声明；通用锁不得遗留已拆出的频道 SDK 或开发工具作为无依赖来源的额外安装项。使用旧锁作为版本偏好重新解析，避免减重时顺带升级无关依赖。官方频道的独立运行包、离线启用及真实依赖闭包校验继续保留。

依赖层和后端安装禁止预编译字节码，发布前导入校验不得向组件写入字节码。后端 wheel 使用本地按名离线安装，避免随机暂存路径进入安装元数据；保留 wheel 摘要追溯。`test_desktop_dependency_lock.py`、`test_layered_channel_build.py` 和 `test_desktop_layer_layout.py` 的真实离线安装回归进入固定前述更新入口，不允许用放宽签名、宿主指纹或协议兼容性实现减重。测量脚本的进程树回收同样受回归保护，不能在基准完成后遗留服务。

默认核心不再安装 Transformers／ONNX Runtime 及仅由它们引入的依赖，完整推理库保留在 `[ml]`，`[full]` 继续包含 `[ml]`。UGSci 公式计算需要的 SymPy 和本地精确分词需要的 Tokenizers 必须作为直接依赖保留。`test_desktop_optional_ml.py` 在新进程中阻断被移除库的导入，执行真实核心、公式和储气数据行为回归；它不能替代干净机器上的完整桌面验收。

原生启动器将 Python 字节码定向到系统用户缓存下的 `qwenpaw/python-bytecode-v1`，覆盖插件贡献的缓存环境配置；目录检查失败则禁写字节码。拒绝应用缓存子目录中的符号链接和 Windows junction；Unix 目录还须归当前用户所有且无组／其他用户权限。普通子进程继承缓存配置，独立 Windows CLI 使用 `-B` 和可继承的 `PYTHONDONTWRITEBYTECODE=1`，隔离频道 worker 保持原有 `-I -B`。缓存故障不得阻止后端启动，也不得恢复向签名组件写缓存。Rust 回归执行真实 Python 导入、重复缓存复用、子进程和失败分支；Python 回归继续实际应用差量，核对最终文件清单。

启动器变化必须通过既有宿主指纹触发完整桌面升级，不得伪装成仅后端更新或调整指纹算法绕过兼容门禁。由浏览器独立启动的 Native Messaging 进程不在本轮运行时缓存覆盖范围内。已安装旧组件中的历史缓存不自动清理；差量不匹配继续走签名全量恢复。

全量和差量 ZIP 写入显式 `ZipInfo` 时必须同时指定压缩级别，不能仅设置 `ZipFile` 的默认级别。仍使用现有 DEFLATE 格式、固定时间戳和完整内容校验；`test_component_compression.py` 验证重复构建字节一致、实际压缩结果，以及签名客户端安装后的数据保留。压缩收益应以实际组件测量，不推导整包或启动收益。

## Windows 安装、常驻守护与插件加载（2026-11-06）

- Windows 更新助手的解压缓冲在单次操作内复用，逐块进度约每 100 毫秒更新一次。全部 ZIP 成员及流写入成功后才能报告解压阶段 100%；该阶段只对应整体进度 70%，软件健康检查与事务提交之后才是整体完成。签名检查、阶段切换、错误日志、失败进度归零、备份、交换及回滚不参与限流。`test_windows_update_extraction.py` 在 Windows 编译实际 C# 源码，并核对每个解压文件、累计分配、非法路径／链接拒绝和后续非法成员不能提前报成功。此套件依赖 Windows .NET，其他平台的条件跳过不算验收通过。
- 原生 daemon 仅在本次启动确认 ready 后转为操作系统的进程退出等待。未就绪时保持原有 60 秒／已初始化 30 分钟超时及失败回滚；退出后仍补读唯一启动回执中的更新重启意图，先处理显式停止，再处理重启、回滚与崩溃退避。不能将可选插件失败等同核心失败，也不能依据旧实例回执提前确认新进程。Rust 回归使用真实临时子进程验证等待期间不再周期探测、关闭、异常退出、超时和快速重启。
- 插件两阶段加载先筛选当前类型及尚未有加载记录的候选，再在工作线程进行依赖排序探测。排序只影响顺序，实际加载仍执行新鲜的依赖准入、启用设置、兼容检查及生命周期锁；锁内复查记录继续保留。启动阶段仍不得联网安装缺失依赖。`test_plugin_startup_perf.py` 的真实插件回归保护阶段过滤、已处理记录不重排和慢磁盘探测期间事件循环响应。
- 完成标记中的每个文件仍须存在且位于插件根目录内。普通文件按父目录集中枚举，目录路径只解析一次；文件链接及重解析点走原有解析检查，不能把链接越界当完整安装。按保留大小写的字符串分组，不能用 WindowsPath 的大小写折叠把不同标记路径合并。无目录列举权限时回退逐文件检查，缺失和损坏标记继续触发原修复流程，不保存跨启动的存在性缓存。`test_bundle_marker_scan.py` 覆盖文件缺失、目录冒充文件、junction、大小写及权限边界。

上述优化不取消 UGSci 测试数据排除，不改变插件健康确认／备份清理时序，也不改变宿主指纹算法。包含原生 daemon 或更新助手变更的版本继续通过完整桌面升级交付。

## Windows Setup 安装开销（2026-11-06）

安装器的完整文件摘要检查在实际取得管理员权限的进程内执行，且先于创建安装目录、停止应用、备份和激活；未提权的转交进程不再重复整包读取。正常 Setup.exe 已由 Windows 清单提权，仍执行原生初检及安装脚本中的完整复核；减少转交进程重复读取只适用于直接运行未提权 install.ps1 的入口，不能混算为正常 Setup 少一次校验。不能通过标记跳过新鲜完整校验。

`windows_installer_io.cs` 编译后执行逐文件 SHA-256、目录大小统计和复制，并在构建时内嵌进受清单校验的 `install.ps1`。校验同时统计安装内容大小；复制按目录枚举和创建，保留空目录、长路径及完整文件内容。缺失、额外、重复或越界文件以及包内链接和 Windows junction 必须拒绝。用户模型、工作区、密钥的备份、原子交换、健康确认和回滚不能为了提速而省略。

可信根目录上方的系统别名通过真实 Windows 目录句柄规范化，源和目标以真实路径判断重叠。用户工作目录根可重定向，只有保留用户目录的复制显式允许源根 junction；包根和内部链接继续拒绝。本轮保留现有用户数据完整备份策略，改用固定四线程 robocopy，原 `/COPY:DAT`、`/DCOPY:DAT`、`/XJ`、重试限制及退出码大于 7 阻止安装的门禁保留。没有旧安装与旧工作目录的首次安装不做全量备份；保留了旧工作目录的首次桌面安装仍可能触发备份。不能以备份耗时解释所有首次安装卡顿。后续若改为迁移范围备份，必须验证后端首次启动的实际写入范围与恢复能力，不能只删除备份调用。

安装阶段与耗时实时写日志并显示在 Setup；提权子进程通过单一流读取转发日志，不重复全量读取，也不把某阶段完成当作安装成功。新失败回归执行真实 Windows PowerShell 子进程并保留非零退出码。Windows 专项套件在固定前后端／更新清单中保留；其他平台的条件跳过不替代 Windows 验证。
