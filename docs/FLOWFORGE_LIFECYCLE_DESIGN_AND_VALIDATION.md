# FlowForge 统一调用生命周期：设计论证与验证

日期：2026-10-15。对应前置分析：`FLOWFORGE_UPSTREAM_REVIEW_2026-10-15.md`。

## 目标与实现范围

让画布、智能体工具、子流程及恢复操作共用运行服务。已接入父子关系、用户/来源会话传播、取消和超时清理、子流程审批暂停传播、基于原图的恢复。保留 QwenPaw 的运行时、JSON 持久化和现有 HTTP/SSE 协议。

参考 LeAgent 提交 `1f16badc834abbd829d3cb7e9f8fcb5b2d57f443` 的[统一执行设计](https://github.com/vixues/LeAgent/blob/1f16badc834abbd829d3cb7e9f8fcb5b2d57f443/docs/technical/execution-topology.md)和[工作流服务](https://github.com/vixues/LeAgent/blob/1f16badc834abbd829d3cb7e9f8fcb5b2d57f443/backend/leagent/workflow/services.py)。本轮实现为本地服务适配，不直接引入上游数据库、运行注册表或 agent 内核。

## 为什么这样改

### 1. 一次运行只有一个服务入口

此前 SubworkflowNode 查询 registry 后自行构造执行器，默认插件又没有注入该 registry。直接补一个 registry 只能让节点执行，不能统一记录和取消。

现在 WorkflowService 在构造时向执行器注入自身；节点通过上下文取得服务。启动及恢复的公共逻辑集中在 `lifecycle.py`，原服务保留 CRUD 与公开方法接口。子节点只负责输入映射、等待结果、传播暂停和输出，不再拥有另一套执行器。

**兼容取舍：** 无 WorkflowService 的裸 WorkflowExecutor 不再执行 SubworkflowNode，而明确报错。使用子流程的调用方应通过服务启动。原有返回子流程输出的回归测试已迁移到这一公共入口，并保留原输出断言；基础节点的裸执行器接口不变。

### 2. 包含关系与恢复关系分开记录

- `parent_run_id`：直接调用方。
- `root_run_id`：整条调用链的根。
- `resumed_from_run_id` / `resumed_by_run_id`：前后两次恢复尝试的关系。
- `trigger_type`：manual、agent、subworkflow、resume。
- `workflow_stack`：该运行继承的流程 ID 路径。
- `user_id` / `session_id`：来源身份和会话。

这些字段写入执行记录，也出现在运行查询中。恢复产生新的运行 ID，但保持根 ID；子流程由恢复中的父流程继续时，直接父 ID 指向新的父运行。调用栈在恢复时重新建立，避免恢复后丢失循环保护。

智能体仍使用独立执行会话，原会话记录在请求上下文 `parent_session_id`；用户身份和 `workflow_run_id`、`root_workflow_run_id` 传入真实运行时入口。身份关联不等于新增授权机制。

### 3. 取消是向下传播的执行动作

服务在同一生命周期锁内记录取消、向执行器发信号、遍历子运行及恢复运行。新子运行会检查父运行状态，禁止取消后继续派生。

执行器同时等待本批节点和 abort 信号；取消或超时会取消并等待本批协程清理，再移除运行中列表及 abort 注册。子流程节点被取消时也通知子运行服务，覆盖父节点等待期间的清理。失败或超时的父运行会清理其后台子运行。

**边界：** Python 协程取消是协作式的。阻塞同步代码、抑制取消的工具和已经提交的外部业务动作无法由此强行撤回；这不是事务回滚。后续业务幂等和补偿仍必要。

### 4. 恢复使用原图和原状态

运行创建时深拷贝、规范化并保存 `flow_snapshot`。恢复优先使用该快照，不重新读取可变的流程定义，因此编辑或删除已保存流程不会改变现有暂停运行。公开运行查询不附带整个快照。

原引擎保留已成功节点的输出和完成状态，只重新执行阻塞节点。子流程节点将子运行 ID 写入状态元数据：子运行等待人工时，父节点也进入等待；恢复父运行时向同一子运行的检查点传递输入。如果子运行已经被单独恢复，父节点跟随现有 continuation，不新开一份流程。

恢复只接受已完成落盘的 paused/waiting_human 运行；已取消、已完成、执行中运行均被拒绝。服务实例锁和持久化 `resumed_by_run_id` 防止同一暂停被再次恢复，HTTP 返回 409。历史无快照记录保留读取原流程的兼容行为，无法享有同等的原图固定保证。

**明确区分：** 工作流检查点恢复已实现；本地 agent 适配器没有经验证的原生智能体检查点恢复接口。因此删除了“把 checkpoint ID 拼成提示后重新聊天”的假恢复，改为返回明确错误且不调用模型。

## 验证证据

执行：`.venv/Scripts/python.exe -m pytest tests/unit/plugins/flowforge -q`

结果：**45 passed**。测试使用真实工作流调度器、子流程节点、JSON 执行仓库/状态仓库和 HTTP 路由；智能体供应商调用使用可控替身，事件适配包括宿主 Message 类型。没有调用实际模型供应商，也未启动上游服务。

新增 `test_run_lifecycle.py` 的 13 个行为用例：

| 行为 | 主要证据 |
| --- | --- |
| 嵌套流程输出与追踪 | 父/根 ID、触发类型、调用栈和持久化记录正确 |
| A→B→A 循环 | 明确失败，仅创建两个运行 |
| 执行中的取消 | 主流程和子流程都取消，等待中的 agent 协程执行 finally |
| 审批后继续 | 父子原图被改写后仍得到原审批结果，前置副作用计数仅一次 |
| 并发重复恢复 | 两线程只有一次恢复成功，另一请求被拒绝 |
| 取消暂停树 | 所有相关运行取消，之后不能恢复 |
| 智能体假恢复 | 返回失败，模型调用次数为零 |
| 重启与流程删除 | 新服务从保存快照恢复父子审批流程，且仍拒绝重复恢复 |
| 智能体工具启动子流程 | 用户、来源会话、父运行和根运行关联正确 |
| HTTP 恢复/取消 | 持久化暂停记录可取消，取消后恢复返回 409 |
| 父运行超时 | 子运行取消，运行中列表及 abort 表清空 |
| 子流程先单独恢复 | 父流程跟随已有结果，总运行数为四，没有重复子运行 |
| 取消后的迟到调用 | 新子运行被拒绝，不新增记录 |

既有测试覆盖节点依赖、SOP 顺序、启动即取消、持久化状态与事件重放等。双向调用测试继续通过。测试报告有依赖弃用提示和 pytest 缓存目录权限提示，未造成失败。

源码通过 `scripts/sync_flowforge_bundle.py --sync` 同步到分发插件；相关回归包含包内容一致性检查。`git diff --check` 通过。

## 仍需单独交付的边界

1. 生命周期锁只覆盖单服务实例；JSON 文件不是分布式锁。多进程 worker、租约及共享队列未实现。
2. “暂停后恢复不重跑已完成节点”不等于任何崩溃时刻都 exactly-once。业务副作用完成而检查点尚未保存时仍需要业务幂等键。运行创建与恢复标记也没有跨文件事务。
3. 本轮恢复的是已落盘的暂停状态，不是进程崩溃时任意正在运行的节点。
4. 未新增工作流 ACL、审批人身份验证、审批待办界面、发布版本管理或失败补偿。流程快照只是运行固定定义，不是完整的发布系统。
5. 多个同时阻塞节点仍沿用引擎现有的恢复数据传递方式；企业审批产品需要进一步提供按节点授权、定向恢复的接口。
6. 智能体工具限制/轮次预算、附件与完整事件映射、外部后端和宿主跨事件循环行为仍需专门集成验证，本轮不将接口参数存在等同于约束已全部落地。

未更改用户已有智能体工具开关，未启动实际业务流程或发布新版本。
