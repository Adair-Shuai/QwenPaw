## 保护范围

## 每轮文件汇总与持久交付（2026-10-30）

- 实际聊天 `HostBubbles` 在终态回答底部挂载 `TurnFileSummary`，通过当前 Agent/会话 scope 和持久 response ID 关联执行尝试。历史恢复保留该 ID；重新生成不覆盖旧尝试归档。旧消息没有真实快照时，保留工具结果提示，不伪造起止差异。
- 原生 Runtime 与第三方 HarnessRuntime 共用 `turn_files/lifecycle.py`，执行前取真实文件基线，完成、失败、取消或流关闭后保存终态。第三方捕获执行目录及绑定项目目录；目录解析失败明确标记覆盖不完整。
- `send_file_to_user` 在内容校验成功后即时冻结交付字节。同轮再次覆盖、后续轮覆盖或删除原文件，不改变已经保存的交付版本；进程异常后仍可读取已经完成持久化的交付。
- 清单区分新增、修改、删除与显式交付，文本按需加载只读 Monaco 差异。已删除文件可读取删除前版本；整轮 ZIP 将删除前文件放在 `deleted-before/`，同轮额外交付版本放在 `delivered-versions/`。快照预览沿用原生 artifact 独立只读标签，不覆盖当前文件未保存草稿或 pending diff。
- 文件工作区增加会话成果入口，汇总明确交付以及本轮 `output/` 下新增/修改的可用版本，分页读取旧轮次。不得扫描共享 output 目录并冒充本会话成果。兼容工具卡按 Agent/会话隔离；路径身份包含 root/source，归档身份额外包含轮次/文件/版本。
- API `/workspace/turn-files` 同时挂载普通及 Agent-scoped 路由，校验 chat/session/agent/user/channel；归档读取只使用服务端文件 ID，不接受客户端读取路径。媒体支持受校验的 `chat_id` 查询参数；header/query 不一致必须拒绝。
- 取消时终态事件可能先于最终归档完成；前端遇 `running` 清单必须继续有界轮询，超时或错误提供重试，不能把空的运行中清单当作“没有改动”。刷新不得复用完成事件之前发出的过期请求。
- 保存位置为 Agent 工作区 `.turn-files`，不修改项目 Git 索引。此目录属于运行时状态，必须排除检查点文件恢复和默认工作区 Git 跟踪。归档按内容哈希去重，独立于检查点的自动清理期限。
- 捕获范围有界：最多 2000 文件、每文件 32 MiB、每次扫描 128 MiB；文本比较最多 2 MiB/20000 行，行数统计另限 256 KiB/4000 行。排除内部状态、常见凭据、依赖缓存、符号链接和 Windows reparse points。超限、读取失败或目录重叠并发都明确提示；起止差异只证明本轮期间发生变化，不证明全部由本 Agent 写入。未绑定目录的任意 Shell 写入不在自动扫描范围，显式交付仍可归档。

固定回归新增 `tests/unit/test_turn_files.py`、`tests/unit/runtime/test_turn_file_lifecycle.py`；前端包含 API、真实 HostResponseCard 挂载、sessionApi 历史映射、TurnFileSummary、成果分页、legacy registry，以及 FilesWorkspace/TabbedEditor 草稿保留集成测试。它们登记在前后端固定执行清单，不得用仅测提取函数替代。
