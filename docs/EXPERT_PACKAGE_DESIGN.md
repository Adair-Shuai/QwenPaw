# UGSci 专家包与领域能力分发设计

日期：2026-11-16。状态：调研与设计提案，未实现专家包安装协议，未发布产物。

## 1. 产品决策

建议把“可安装、可验证、可升级的领域专家”作为市场交付单位。专家包声明它需要的技能、方法库、工具、知识资源和运行环境，由平台完成依赖获取、配置和验证。

用户安装一次专家，平台装配完整能力；公共方法库和运行时独立发布并按版本复用。专业能力可以持续增长，无需把所有行业库预装进桌面核心。平台必须区分“文件已下载”“专家已创建”和“业务能力已可用”。

沿用仓库已有《工具·技能与引擎架构方案》的概念：引擎提供执行能力，工具暴露操作，技能组织专业步骤，专家装配这些能力。方法库归属领域计算或执行能力层；MCP 是工具接口和连接方式，不承担全部依赖管理。

## 4. 资产模型

| 对象 | 内容和职责 | 生命周期 |
| --- | --- | --- |
| 专家包 | 专家说明、能力列表、所需包引用、配置表单、验收方案 | 市场中不可变的版本化发行物 |
| 技能 | 专业步骤、工具使用规则、参考资料、模板 | 可复用、版本化；包内可附带，也可引用独立包 |
| 方法库 | 可执行算法/文件处理/校验逻辑、输入输出契约、适用范围、基准用例 | 可独立测试发布，允许多个专家使用 |
| 工具提供者 | 将方法或外部服务暴露为工具；可以是现有宿主插件或 MCP 服务 | 单独记录工具协议、进程和健康状态 |
| 引擎/运行时 | Python、Node、Java、求解器或远程计算服务 | 按平台安装；受许可限制的软件只检测并连接 |
| 知识资源 | 可分发资料、索引配方、来源和版本描述 | 与用户资料分离；私有资料由用户导入后本地建索引 |
| 专家实例 | 已选择的专家版本、依赖锁、配置引用、工作区、用户定制 | 用户所有；升级专家包保留对话、数据、记忆和定制 |

一个方法库可以由一个 MCP 服务暴露，也可以通过现有可信插件接口暴露；不要求每个函数启动一个 MCP 服务。专家清单引用提供者，提供者声明其方法库与运行时依赖，避免专家和 MCP 各自安装一套互相冲突的 Python 库。

方法至少声明：稳定 ID、版本、输入/输出 Schema、单位与量纲、适用条件、来源依据、资源要求、错误语义，以及已知答案的验证用例。工具返回结构化数据和产物引用，LLM 负责选择方法、解释结果与组织报告；输入约束和数值验收由代码执行。

## 5. 包与锁定清单

建议引入独立的专家包清单，保留现有插件格式作为依赖类型。不要直接把一组新字段塞进当前只接受提示模板的发布接口。

下例是拟议协议示意，不是当前可上传的文件；示例专家/MCP 版本及能力 ID 均待首版发行确定。

```yaml
schema_version: 1
id: ugsci.reservoir-simulation-expert
version: 0.1.0
kind: expert
host:
  capabilities: [expert-package-v1, managed-mcp-v1]
instructions: expert/AGENTS.md
skills:
  - path: skills/reservoir-simulation-expert
  - path: skills/reservoir-model-diagnostics
dependencies:
  - id: ugsci.reservoir-methods-mcp
    kind: mcp-local
    version: 0.1.0
    required: true
features:
  eclipse-binary-io:
    dependencies: [ugsci.reservoir-io-eclipse]
    default: false
  commercial-simulation:
    connections: [simulator]
    default: false
configuration:
  simulator:
    kind: external-engine
    required: false
  domain-manuals:
    kind: local-documents
    required: false
verification:
  profile: verification/basic.json
```

发行流水线另外生成每个目标平台的 `release.lock.json`，包含所有直接和间接依赖的精确版本、SHA-256、大小、不可变下载地址、签名关联、Python/Node/Java 版本与 ABI、OS/架构、启动入口及工具契约摘要。专家清单和锁定清单都属于签名覆盖内容。没有对应平台完整产物时，该平台不显示可安装。

支持的可选能力组合也必须有经过验证的锁定结果。首版只提供少量固定组合，避免用户任意组合 extras 后现场重新解析依赖。作者可以在源码中维护版本范围，但用户安装消费已经验证的精确锁；不能依赖 `latest`、可移动 Git 分支或无摘要的临时下载。

渠道目录保留专家的展示信息，指向不可变发布清单。UGSci 渠道统一分发可合法再分发的技能、方法库、MCP 服务与运行时；远程 API 分发连接模板，商业求解器分发适配器与配置说明。不能把远程服务或需要用户许可证的软件描述为已随包安装。

小型资源可以直接装进专家归档；大型依赖按摘要分开存储下载。以后离线包可以导出同一份锁及依赖归档，不重新定义一种安装语义。许可证、远程 API 和用户资料的前置条件仍存在。

## 6. 运行隔离与复用

采用“共享不可变文件，隔离依赖环境与用户状态”：

- 下载缓存按摘要复用；环境按平台、ABI 和完整依赖锁摘要区分。锁完全相同时才复用环境，不能只看库名或 Python 大版本。
- 新领域 Python 方法默认运行在受管理的独立环境与子进程中；Node 使用包内固定依赖；Java/JAR 绑定经验证运行时。不要把任意专家的科学计算库装入宿主 Python 环境。
- 每个专家实例独立配置、工作目录和凭据引用。同一环境可复用文件，但默认启动独立进程，避免工作区、认证和状态串用；服务明确支持租户隔离后再考虑共享进程。
- 现有需要宿主内执行的插件继续走当前共享依赖门禁。不支持并存的插件/引擎发生冲突时，安装计划明确列出冲突并阻止激活，不宣称所有包天然可以多版本共存。
- 子进程和 venv 解决依赖冲突，不等同于 OS 安全沙箱。首版限制为审核发布者的产物，声明访问工作区/外部网络等权限；无法落实的强隔离能力不能标注为已支持。
- 启动路径由宿主按安装位置生成，使用参数数组，替换本机硬编码路径；Windows 路径、空格、中文、长度限制，以及 macOS 架构、动态库、可执行文件签名均进入平台验收。

包目录只读；凭据在宿主凭据设施中保存，包只声明字段与引用。环境变量只注入需要它的子进程。用户文件、索引、报告、日志和缓存放在包外的数据目录。

## 7. 安装事务与可用状态

建议新增后端 `ExpertInstallService`，由 UGSci 页面提交一个任务。后端复用已有技能、MCP、插件与引擎安装器，前端不再串接多次写操作承担事务责任。

拟议流程：

```text
获取并验证发行清单 → 解析依赖与平台兼容 → 生成安装计划
→ 下载并核验 → 暂存依赖和环境 → 收集必要配置
→ 真实启动与能力验收 → 原子切换专家绑定 → 就绪
```

安装计划包含实际新增下载量、磁盘需求、复用项、受影响专家、外部软件要求、所需配置和可能重启项。用户点击安装即可执行已经展示的计划；API 密钥/OAuth/本机许可证配置在确实需要时收集。

任务持久化阶段、产物摘要、重试次数和错误码，支持幂等请求、断点恢复、取消和重启后恢复。网络失败可以复用已核验缓存；签名、文件内容或平台不匹配不能通过更换下载源绕过。

就绪条件是：所有必需技能可发现，方法环境可用，MCP 完成握手且必需工具契约匹配，代表性无副作用调用产生符合断言的结果。仅列出工具、import 成功或存在目录均不足以判定业务可用。需要外部付费调用的验证必须明确费用和用户意图，不由默认安装自检偷偷执行。

两类状态分开持久化：安装任务状态（排队、下载、配置、验证、完成、失败、取消）与专家能力状态（可用、需配置、部分可用、不可用）。必需依赖未满足不能显示“可用”；可选模拟器未配置时，明确哪些能力仍可使用。运行前重查关键外部连接与凭据状态，避免安装时成功后长期显示错误状态。

失败时保留旧专家版本；新建专家可以保存为“安装未完成”草稿，保留重试入口，但不参与生产任务路由。暂存副作用由补偿日志恢复：仅解除本事务创建的绑定，不删除另一专家或并发安装已经使用的依赖。

外部安装器未必支持数据库事务，因此“原子”指最后的可见绑定切换。共享安装、引用计数、运行租约和恢复需协调，不能依赖前端删除几个文件实现回滚。

## 8. 用户界面

市场专家详情优先回答：可以完成哪些任务、输入什么、输出什么、有哪些已验证方法、当前电脑能否安装。技术依赖放在可展开的安装详情里。

一次安装完成后直接进入“专家·协作”，显示能力清单和一个示例任务。不要要求用户先理解 MCP、pip、Java 再去多个页面拼装专家。

油藏专家示例：

| 能力 | 首次安装后的状态示例 | 可采取的操作 |
| --- | --- | --- |
| 基础文件检查、实验设计、评分方法 | 真实自检通过后可用 | 使用合成数据试运行 |
| 特定二进制格式读取 | 未选择扩展时未安装 | 安装对应格式组件 |
| 版本化手册检索 | 需导入本地授权资料 | 选择资料并建立索引 |
| 商业模拟器运行 | 需配置 | 指定安装位置/远程服务并检测许可证 |

“工具·技能”继续提供细项管理；专家详情提供其装配清单与修复入口。渠道、下载缓存、运行环境策略等全局设置统一进入 `/settings/ugsci`，不新增主侧栏设置入口。

## 9. 发布、升级与卸载

作者提交专家源码和依赖声明；渠道构建按平台生成锁和产物，执行静态校验、真实启动与领域基准，完成审查与签名后发布。市场索引最后更新，避免用户看到不存在或尚未验证的产物。

发布校验覆盖：依赖闭包、平台与许可、启动入口、路径安全、凭据泄漏、包内完整文件摘要、真实工具契约、领域样例预期与误差容限。方法的已知答案测试、LLM 任务选择质量评测、真实工程项目验证分别记录，不能互相替代。

明确禁止包含用户工作区、私有手册、许可证、令牌、个人记忆以及 `plugins/bundle/ugsci/visualization/data`。示例数据只使用允许发布的独立合成或开放数据集，不能借专家包绕过现有打包排除规则。

升级先准备和验证新依赖，再切换专家实例引用。正在执行的任务持有旧锁和运行租约；等待任务结束或保留旧环境并存，不替换运行中的库。用户修改的技能/说明采用“包基线 + 用户覆盖”或显式冲突处理，不能静默覆盖。

回滚恢复上一份完整专家锁与绑定。涉及用户数据格式迁移时先备份并声明是否可逆；不能保证可逆时，不展示无条件回滚。卸载先移除实例绑定，只有引用计数和运行租约都归零的依赖才进入清理候选。用户数据默认保留。

首次实现需要升级后端安装/发布能力与 UGSci 插件。是否需要完整桌面包仍由现行最低核心版本、协议和宿主指纹检查决定；本方案不绕过它们。当前大批改动不能据此改称“只更新专家包即可”。

目标是首次完成基础能力升级后，在宿主支持的协议与运行能力范围内，新专家、技能和方法更新可以独立走 UGSci 渠道。新增宿主 API、原生能力或不兼容运行时仍需要相应升级。不能承诺平台核心从此无需更新。

## 10. 后端边界与数据建议

以下 API 名称为设计建议，具体前缀在实施时遵循现有路由约定：

| 接口 | 行为 |
| --- | --- |
| `POST /expert-packages/plan` | 只读解析平台发行锁，返回下载、冲突、配置和兼容性计划 |
| `POST /expert-installations` | 校验计划摘要仍有效，幂等创建安装任务 |
| `GET /expert-installations/{id}` | 返回阶段进度、可恢复错误与待配置项 |
| `POST /expert-installations/{id}/configure` | 绑定受控配置/凭据引用，继续验证 |
| `POST /expert-installations/{id}/cancel` | 安全取消，执行必要补偿 |
| `POST /experts/{id}/upgrade-plan` | 比较两份锁及用户覆盖，列出影响 |
| `POST /experts/{id}/verify` | 重做能力检查，刷新就绪状态 |

持久化对象建议包括发行元数据、安装事务日志、已核验产物、运行环境、专家绑定、配置引用与验收结果。数据库只保存凭据引用；不得把密钥写入任务日志、导出锁或发布包。

核心层负责包完整性、受管理环境、事务、进程和状态接口；UGSci 插件负责领域清单、市场与专家体验；方法作者负责算法契约、工具实现和基准用例。插件更新器、领域引擎安装器与专家装配器共享底层设施，避免产生第三套独立更新机制。

运行记录保存专家版本、依赖锁摘要、方法/引擎版本、模型标识、输入摘要、单位、参数、随机种子、产物与验证结论。目标首先是确定性方法可复跑和执行证据可追踪；LLM 与远程服务的变化意味着不能承诺整段智能体行为位级复现。

## 11. 实施顺序与首版边界

**第一阶段：一个专家完整跑通。** 采用现有油藏专家，提供基础技能、现有 MCP 确定性方法与基础读写库。实现发行清单/平台锁、受管理 Python 环境、UGSci 下载、配置、持久化安装任务、真实自检和旧版本保留。在 Windows x64、macOS arm64 干净环境分别验证；其他平台未验证不开放安装。基础包不要求商业模拟器或私有手册。

首版采用审核发布者、固定依赖组合，消费预构建产物，不开放任意 shell 安装脚本与客户端源码构建。对于暂不能隔离的现有共享插件冲突，明确阻止；不要以覆盖宿主环境换取一键安装。

**第二阶段：复用和扩展。** 增加二进制格式组件、NeqSim/Java 等现有引擎适配；验证两个专家共享同一版本、两个隔离环境使用不同版本、升级回滚、垃圾回收与离线导出。补齐自动发布工具与分平台 CI。

**第三阶段：规模化领域市场。** 增加 MCPB/其他插件格式适配、远程计算与企业私有渠道、更多领域能力、任务级质量评测与版本准入。可在稳定后增加经测试的更多依赖组合，避免一开始承担通用包管理器的全部复杂度。

首版验收：

1. 干净机器无开发仓库、无用户预装 Python/Node 时，能从 UGSci 完成所宣称平台的基础专家安装与实际调用。
2. 断网、关闭程序、重试同一任务均不会产生重复专家、丢失状态或误删共享依赖。
3. 缺少必需技能/方法、错误工具 Schema、自检数值错误时，专家不能进入可用状态。
4. 可选资料/模拟器缺失只影响对应能力，界面准确解释并给出配置入口。
5. 篡改签名、错误平台、错误文件摘要、缺少传递依赖时，在激活前拒绝。
6. 升级失败保留旧版；成功升级保留对话、工作区、配置与用户覆盖；运行中任务不被换环境。
7. 中文与空格路径、Windows 长路径、macOS 原生依赖加载均通过真实安装验收。
8. 安装器下载的是渠道已验证的精确依赖，不访问作者机器路径或在终端用户机器构建 Git 依赖。

实施时按 `AGENTS.md` 保留固定回归清单，新增实际市场页面安装流程与后端事务测试。涉及相关模块后执行 `npm run test:fork-features`、类型检查、`python scripts/verify_fork_regressions.py`、`python scripts/verify_update_regressions.py` 及相应方法库集成测试；同步两份 UGSci 插件源码和打包产物。不能把单元测试通过等同于完成上述跨平台验收。
