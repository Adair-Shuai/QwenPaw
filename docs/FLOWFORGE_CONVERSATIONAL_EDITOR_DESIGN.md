# FlowForge 持续对话编辑器前后端设计

设计稿 v2，2026 年 11 月 13 日。供产品交互、后端实现、前端实现与回归验收共同使用。本版采用专用工作流专家、按工作流隔离的持续会话，以及带验证来源的调试经验库。

用户可以在同一段对话里讨论工作流、修改画布、应用方案和验证修复。刷新页面、返回工作流、应用修改与手工编辑都能继续这段对话。每次实际修改以当时的最新草稿和服务端修订为依据，聊天记录保存用户的要求、AI 的答复和操作结果。

默认交互采用右侧停靠聊天栏。AI 先给出简短答复，涉及改图时附带变更卡片，用户通过卡片预览和应用。运行验证由卡片中的明确操作发起，结果回到原对话。

## 专用工作流专家

### 专家配置与职责

在专家中心配置专用的“工作流助手”，建议稳定 ID 为 `flowforge_assistant`。模型、系统指令、技能及启用状态使用现有专家配置。通过宿主 `AgentBuilder` 与专家工作区的 `stream_query` 接入正常专家运行时，支持对话、工具调用、停止及持久化恢复。

该专家负责理解目标、解释流程、诊断错误、提出和校验修改，以及整理调试经验。每个工作流通过独立会话使用这一专家。

`authoring_agent_id` 指向工作流助手，决定编辑对话的模型、指令和工作流工具。`execution_agent_id` 指向当前流程的执行专家，决定业务节点可用的工具、模型及权限。节点目录查询、方案校验、应用及验证都携带明确的执行专家。界面显示“工作流助手”和“执行专家”，便于核对角色。

FlowForge 保存专用专家的 ID 绑定，并在启动会话时验证其配置与技能是否可用。需要用户配置绑定时统一放入 UGSci 设置，入口链接至现有专家中心的模型、指令和技能配置。

### 工作流知识与操作工具

专用专家预置版本化的工作流技能包，随插件更新基础知识。包内包含节点及端口用法、变量绑定和表达式、JSON Schema、多输出槽位、控制分支、重试超时、人工审核、子流程、修订保存和常见排错案例。专家中心的个性化补充指令独立保存。

接口知识来自当前服务的请求模型和工具 Schema，节点能力来自当前执行专家的实时目录。每轮记录插件版本、知识包版本和能力目录指纹，经验匹配时检查适用条件。

专家通过有明确输入输出的工作流工具访问服务，核心职责如下。

| 工具能力       | 服务行为                                                     |
| -------------- | ------------------------------------------------------------ |
| 读取当前上下文 | 返回绑定工作流的最新草稿、保存修订、选区和执行专家能力       |
| 读取运行诊断   | 校验运行归属并返回实际错误、输入输出、配置和事件的公开投影   |
| 检索工作流经验 | 返回当前流程记录及适用的通用工作流经验，标明证据与状态       |
| 提交修改方案   | 接收候选文档，通过既有差异、范围、能力和结构校验生成动作卡片 |
| 请求澄清       | 将问题和选项写入当前会话，等待用户的下一条消息               |
| 准备修复验证   | 返回采用当前修订与历史业务数据的真实调试计划                 |
| 记录调试观察   | 写入问题、假设、尝试和依据，验证状态由真实运行结果更新       |

工具调用中的账户、流程和会话归属由服务端绑定上下文解析。一次工具调用使用稳定工具调用 ID 和轮次 ID 记录幂等回执。应用、回退和开始验证沿用当前卡片对应的服务操作。专家任务的授权范围贯穿读取、修改及调试入口。

### 持续会话接入

一个 FlowForge 会话绑定一个持久的专家运行时会话 ID。继续发送、关闭再打开和刷新时，恢复同一绑定。新对话创建新的绑定，同一工作流的经验记录可以继续检索。

会话键包含工作目录、账户、工作流和对话 ID。执行专家作为每轮上下文记录。用户切换执行专家后，当前工作流继续对话，服务重新读取能力目录，并按新能力检查待应用方案。

目前工作流节点使用的 `engine/adapter/agent_runtime.py` 在 `stream` 中丢弃传入的 `session_id`，实际调用创建随机 `flowforge:{uuid}`。持续编辑需要新增专用桥接入口，持久传递会话 ID，接收原生文本、工具和最终状态事件。节点执行适配器继续承担一次节点任务的职责。

FlowForge 数据库保存可见消息、卡片和操作回执，宿主会话存储保存运行时上下文状态。桥接记录保存轮次及宿主消息关联，按消息 ID 幂等投影。恢复时核对完成回执、工具回执和最后同步的轮次，已有动作引用按原记录恢复。状态落盘窗口中断时标记待核对，必要时依据持久消息与操作回执重建运行时上下文，工具结果作为已完成记录加载。

## 调试经验的保存与使用

### 每次调试保留记录

每次调试都形成记录，覆盖观察到的问题、原因假设、尝试的修改、验证输入及结果。失败的尝试和仍待验证的判断也保存，并展示各自状态。

每条记录包含账户、工作流、执行专家、节点类型、工作流修订、插件及知识版本、错误特征、原始运行引用、动作引用、验证运行引用、适用条件、时间和来源。原因解释作为带证据的判断保存，运行状态和输入输出来自实际记录。

例如一次脚本字段错误保存其字段不一致、采用的修改、`0`、`false` 与 `null` 的处理，以及当前修订的实际验证结果。后续继续调试时，专家可读取之前失败的修改及其输出。

### 当前流程经验与通用经验

流程经验按工作流隔离，保存该流程的业务约束、数据特征、调试记录和待解决问题。关闭或删除某一段聊天后，工作流经验通过自己的保存与清理入口管理。

可复用经验从有实际验证记录的问题中提炼，内容包括错误模式、适用节点和版本、修复规则、验证方法及来源记录。服务端脱敏并提取通用内容后，可在同一账户的其他工作流中检索。业务名称、原始业务输入和运行日志通过各自流程的来源引用访问。

经验状态采用 `observed`、`hypothesis`、`verified` 和 `invalidated`，调试尝试另记成功、失败或中断。新的反例或版本变化会更新适用状态，旧证据继续可追溯。通用规则的生效取决于真实验证及当前适用条件。

### 让经验进入下一次任务

每轮开始先读取当前工作流的已确定要求、未解决问题和相关调试记录，再按错误特征、节点类型、接口版本及执行专家能力检索适用的通用经验。上下文明确给出命中经验、适用条件和证据来源，专家据此诊断并调用当前接口复核。

结构化经验库放在 FlowForge 数据库，作为调试事实和状态的持久来源。通过宿主 `MemoryBackend` 接入工作流专用记忆后端，将宿主会话 ID 映射到当前工作流作用域，复用已有记忆检索机制。检索返回当前流程数据及符合条件的通用经验，每次自动记忆也使用相同作用域。单条待验证推断按其状态参与检索。

异步经验整理和自动记忆在入队时固定账户、工作流、会话及来源记录，消费时使用任务保存的上下文。整理任务和原始调试记录在同一事务提交，后台失败后可以按任务 ID 重试。工具权限和数据归属在读取来源及写入经验时重新核对。

验证完成后，由服务端将实际结果追加到对应调试记录，专家再提炼经验。经验生成失败时保留已写入的问题、操作和运行引用，恢复后可继续整理。同一运行、动作和经验来源使用唯一键去重。

### 前端经验入口

聊天栏顶部显示工作流助手、当前流程和执行专家。提供“本流程经验”入口，查看已解决、待验证和仍未解决的问题，并能定位原运行和修改卡片。

调试消息显示“问题已记录”，验证完成后显示“修复已验证”或实际失败状态。用户可以编辑经验总结、纠正错误判断、标记失效或删除指定经验。使用通用经验时展示可展开的来源和适用条件。聊天历史和经验各自提供清理操作。

## 产品行为

### 连续对话

- 每个账户和工作流拥有独立的工作流助手会话列表，打开时恢复最近使用的会话。执行专家记录在每轮上下文中。
- 首次发送时创建会话。新对话创建另一条记录，旧会话可从历史中打开。
- 新工作流沿用先创建空工作流再进入编辑器的入口，首次发送关联该工作流的会话。
- 关闭聊天栏保留输入文字、消息、当前变更卡片和后台任务。刷新后从服务端恢复消息与任务状态，本地恢复尚未发送的文字。
- 应用后在原卡片上显示实际修订，下一条消息基于当前画布继续处理。
- 点击历史消息只查看当时的内容。用户通过“基于此方案继续”明确选择一个待应用方案作为下一轮上下文。
- 会话默认持续保留，用户可以删除。可执行方案的有效期独立于聊天历史，过期方案提供“按最新画布重新检查”。
- 删除工作流沿用现有删除语义，关联会话和流程经验转入归档并展示删除状态。显式清理会话时删除其消息、上下文和临时准备记录。工作流经验、已保存版本及实际运行各自按其生命周期管理。

### 普通讨论与修改

输入框默认使用“自动”。询问含义、失败原因和方案优劣时，AI 返回说明。明确要求改图时返回说明和变更卡片。用户也可选择“仅讨论”，在该轮获得解释或计划。

需求缺少影响结果的关键条件时，AI 在消息中给出问题及简短选项，用户可以点选或自行补充。回答作为新的消息保存，下一轮可以读取原问题。

示例对话使用同一个输入框完成。

1. 用户询问“这个节点为什么失败”。AI 结合记录说明 `sale` 与 `sales` 的字段差异。
2. 用户要求“改一下，空值也处理”。AI 展示代码和参数变更卡片。
3. 用户点击“应用并保存”。卡片记录实际保存的修订号。
4. 用户要求“再加失败重试两次”。AI 读取当前草稿生成下一张卡片。

### 手工修改与方案分支

生成期间仍可编辑真实画布。发送时固定该轮的草稿、选区和运行来源，后续编辑作为新的草稿变化处理。

待应用方案保存在消息卡片中。用户继续调整该方案时，输入框上方显示“基于待应用方案”和可移除的引用。服务端先将该方案与当前草稿合并，再生成下一轮候选文档，后续卡片包含此前尚未应用的累积修改。

输入框中的范围标签显示“整个工作流”或选中节点名称。范围在发送时固定。切换选区会更新下一轮请求的范围，已有卡片保留自己的范围及来源。

### 修复后的验证

运行详情和画布的“AI 修复”进入当前工作流的会话，并附上节点、运行和修订引用。已有会话继续保留，修复消息携带独立的诊断来源。

修复方案应用后，卡片提供“用本次输入验证”。用户先看到待执行节点、采用的修订、输入来源和复用的历史数据，点击开始后创建真实调试运行。通过、失败、暂停审核及取消结果均作为运行卡片回到原消息附近。失败卡片提供“继续修复”，引用这次新的失败记录。

## 前端布局

### 工作区空间

| 可用工作区宽度 | 布局                                                                               |
| -------------- | ---------------------------------------------------------------------------------- |
| 至少 900px     | 画布和聊天栏并排。聊天栏默认 400px，可在 320px 至 560px 间拖动，画布至少保留 480px |
| 600px 至 899px | 聊天栏以侧面覆盖层打开，宽度取 440px 与可用宽度中的较小值                          |
| 小于 600px     | “画布”和“对话”切换为整宽视图，返回时保留视口和消息位置                             |

宽度依据工作区容器测量，侧栏、节点库及运行面板占用均计入。拖拽分隔条支持指针、键盘、取消和失焦释放。宽度按账户保存，窗口缩小时重新约束。

聊天栏打开时，节点属性通过画布内的可关闭浮层编辑。节点库、属性、运行面板和聊天栏共同参与尺寸计算。底部运行面板沿用现有拖拽高度，聊天内的运行卡片可以打开完整运行详情。

### 聊天栏结构

1. 顶部显示“AI 编辑”、当前会话名称、历史入口、新对话和收起操作。
2. 中间显示消息。用户要求、AI 答复、澄清选项、变更卡片、冲突卡片和运行卡片均有稳定消息 ID。
3. 底部固定输入区。范围与来源引用放在输入框上方，发送与停止使用同一主操作位置。

顶部附带可核对的工作流助手身份和“本流程经验”入口。执行专家作为独立的流程上下文显示，切换后给出能力目录更新状态。

答复优先展示结论及必要说明。字段差异、完整文档、原始错误和事件放入可展开详情。错误反馈紧邻对应请求，保留输入文字并提供重试。

首次打开时保留简短输入占位和少量实际可用的示例。已有消息时，示例入口收进输入区菜单。状态提示使用真实任务阶段，生成期间可编辑下一条输入。

### 变更卡片

卡片展示简短变更说明、涉及的节点、校验状态和两项主操作“预览变更”“应用并保存”。展开后显示字段路径、原值与新值。点击节点名称定位画布。

预览由用户显式打开，画布顶部显示“变更预览”和“返回编辑”。预览使用现有新增、修改、删除节点及连线样式。返回编辑恢复真实草稿和原视口，聊天保持打开。

应用前先进行最新草稿检查。无冲突时采用合并后的预览。检查导致候选内容变化时，卡片标明此次合并的来源并更新差异，用户确认当前差异后应用。存在冲突时原位显示冲突卡片。

应用成功后保留卡片，并显示“已应用 · 修订 7”等实际结果。卡片提供“回退此修改”，先展示逆向差异，再确认保存为新修订，完成后记录“已回退为修订 8”。画布工具栏的撤销继续返回草稿，其保存状态由原编辑器展示。

### 冲突卡片

冲突以节点和字段为单位显示原值、当前值及 AI 建议。当前值标明来源于本地草稿或服务端新修订。

例如 AI 将超时从 5 秒改为 30 秒，而用户已手工改为 10 秒，卡片提供“保留当前 10 秒”和“采用 AI 的 30 秒”。用户可以逐项选择，也可以继续发消息说明要求。选择后服务端重新计算整张卡片及结构校验。

节点删除、节点类型替换、同一输入的连接变化按相关依赖组合展示，整组解决后重新验证。普通定位移动与代码修改可独立合并。

### 可访问性与语言

- 消息流使用 `role="log"`，任务阶段适度播报，新增消息期间保留用户当前阅读位置。
- 输入法组合输入期间 Enter 保持输入。常规 Enter 发送，Shift 加 Enter 换行，界面提供快捷键说明。
- 颜色配合文字和图形表达状态。焦点能返回发起预览、打开详情或解决冲突的控件。
- 沿用宿主主题和 FlowForge 中英文机制。业务名称、脚本、提示词与变量标识保持用户原文。
- 请求切换账户或工作流后，旧消息和请求继续归属于原会话。新页面先加载确认的身份与会话作用域，再展示其内容。切换执行专家时保留当前流程会话，重新核对能力、来源运行及方案适用性。

## 服务端模块

接入宿主专家运行时，复用当前 `WorkflowService`、SQLite 工作流仓库、专家目录、结构校验和运行生命周期。

| 位置                              | 实现职责                                                                                 |
| --------------------------------- | ---------------------------------------------------------------------------------------- |
| 新增 `conversation_repository.py` | 会话、消息、轮次、上下文、卡片、准备记录、经验和事件的持久化，使用工作流仓库同一事务连接 |
| 新增 `conversation_service.py`    | 接纳消息、组织上下文、启动后台生成、取消、恢复查询以及校验会话归属                       |
| 新增 `authoring_merge.py`         | 规范化字段差异、三方合并、冲突及逆向差异计算                                             |
| `authoring.py`                    | 复用凭据占位、节点目录和差异逻辑，为专用专家提交的候选文档生成可信动作卡片               |
| 新增 `authoring_agent.py`         | 绑定专用专家及持久宿主会话，注入工作流工具，转换原生运行事件并恢复状态                   |
| 新增 `authoring_memory.py`        | 接入作用域明确的记忆后端，检索流程经验及通用规则，整理调试记录和验证证据                 |
| `flow_repository.py`              | 事务内完成新修订、应用结果和操作记录，提供同连接的内部方法                               |
| `router.py`                       | 增加会话、事件、准备、应用和验证路由，解析宿主身份及专家作用域                           |
| `service.py`                      | 组合新会话服务与现有工作流、调试服务                                                     |
| `repair.py`                       | 构造原始失败和后续验证失败的有界公开诊断上下文                                           |
| `lifecycle.py`、`debugging.py`    | 复用真实调试运行，补充验证请求与运行 ID 的持久关联                                       |

原有 `/authoring/proposals` 及应用接口继续服务既有调用方。新会话接口使用独立的消息与卡片生命周期，双方共享规范化、范围校验和保存逻辑。

内部工作流快照、候选文档和准备文档遵循现有工作流存储的访问边界。模型请求继续使用凭据占位映射。消息、摘要、差异、事件和公开上下文经过脱敏投影，直接返回完整内部文档的行为需要改成明确的公开 DTO。编辑器通过现有受控工作流接口取得实际草稿。

完整消息长期保存，列表按序号分页，首屏读取最近 50 条。完成轮次的中间事件可压缩，读取过旧事件游标时返回重同步信号，由客户端重新读取消息和当前任务。会话摘要保存已确定要求、待回答问题、引用来源及关键操作结果，能够追溯到原始消息范围。

消息块使用 `text`、`clarification`、`action_ref` 和 `run_ref` 等明确类型。消息保存稳定的动作及运行引用，读取时附带这些资源的最新公开状态。活动轮次在 `queued` 和 `running` 状态上通过会话内唯一约束与状态比较并交换协调。

应用卡片保存实际结果和逆向变更依据。准备记录使用当前提案的 1 小时有效期，过期后可重新准备。历史卡片、消息及已应用结果具有独立的持久记录。

## 消息处理与模型协议

### 接纳与执行

1. 校验账户、工作流、会话归属、专用专家配置和请求大小，在事务内通过请求 ID 接纳用户消息、上下文和轮次。
2. 返回 `202` 及已持久化的消息 ID、轮次 ID，前端订阅事件。
3. 会话服务在受管理后台任务中调用专用专家运行时，显式携带账户、流程、宿主会话 ID 和本轮执行专家上下文。HTTP 断开后任务可继续。
4. 终态 AI 消息、方案卡片和完成事件在一个事务提交，客户端可回放或重连。

编辑专家由服务端 `authoring_agent_id` 绑定解析。业务工具目录通过 `execution_agent_id` 查询，并注入本轮上下文及提交方案工具。宿主专家工作区中的模型和专业技能用于编排任务，候选工作流按本轮执行专家的能力完成校验。

模型调用和运行等待发生在事务外。SSE 每批读取有界事件，慢连接和断开的订阅独立释放，任务继续通过持久状态记录进展。

每个会话同一时刻执行一轮。生成时输入框保持可编辑，主按钮提供停止。另一标签页同时发送时返回 `TURN_IN_PROGRESS` 和实际活动轮次，界面连接该轮次并保留新输入。不同会话可以独立处理。

事务先查询幂等回执，再检查新请求的会话尾序号和活动轮次。同键同参的网络重试能够取得原结果，会话尾序号已推进时的新请求取得最新序号和恢复入口。消息沿用当前 20000 字要求上限，草稿沿用 200 节点上限，诊断数据沿用现有有界投影。

服务接纳后崩溃的活动轮次在重启时标记 `interrupted`，消息及部分真实阶段保留。用户重试创建带 `retry_of_turn_id` 的新轮次。网络重试同一请求 ID时返回原轮次，参数不同则返回幂等冲突。

### 每轮上下文

专家输入包含当前草稿、待继续方案引用、选区、执行专家可用节点和工具、会话摘要、最近完整消息、命中的工作流经验，以及本轮明确引用的失败或验证记录。专用工作流技能和接口契约通过专家运行时加载。

浏览器草稿提交 `draft_owner_id`、递增 `draft_sequence` 和已知保存修订。服务端取得该修订的历史文档及当前保存文档，计算并发修改的合并。可以合并时得到本轮有效草稿，返回上下文更新事件。客户端只有在本地草稿序号仍匹配时接纳这份草稿，期间新编辑继续保留。冲突通过消息卡片解决，普通讨论可以继续。

需要继续待应用方案时，先把该方案合并到本轮有效草稿，作为模型的起点。新卡片记录有效草稿为基准，包含所有尚未应用的累积变更。每张卡片保留父卡片与来源消息。

失败记录通过 `build_repair_context` 从服务端读取。模型看到实际记录的修订、错误、配置、输入输出可用性和事件。后续验证通过新的运行引用进入上下文，保留旧诊断的来源。

摘要和最近消息按模型上下文预算组织，较早消息可按需读取。当前有效草稿、明确引用及未解决问题优先保留。摘要压缩覆盖到具体消息序号，压缩前后的原始消息继续保留。

### 返回类型

桥接层将专家的自然语言、澄清工具结果和修改工具结果转换为可校验的前端消息类型。

```typescript
type AuthoringReply =
  | { kind: "reply"; text: string }
  | {
      kind: "clarification";
      text: string;
      question: string;
      options: { id: string; label: string; value: string }[];
    }
  | {
      kind: "proposal";
      text: string;
      action_id: string;
      warnings: string[];
    };
```

专用专家调用提交修改工具时，服务端对候选文档计算差异、验证能力和范围，并返回持久动作 ID。自然语言答复引用该动作 ID，前端据此显示卡片。答复、澄清和修改使用各自的消息分支。“仅讨论”轮次启用读取、检索和澄清能力，编辑轮次启用提交及校验方案能力。工具输入不合法时返回结构化错误，专家可在同轮修正，并记录实际尝试。

桥接层消费宿主原生文本、工具调用、工具结果及完成事件。“已读取画布”“正在检查方案”等阶段来自实际服务步骤，工具调用和卡片可在同一轮出现。流式文本复用宿主事件转换，区分增量与累积快照，以最终消息完成状态提交终态，并保留实际用量和取消语义。

## 合并与应用

### 规范化与比较

所有指纹由服务端对规范化文档计算。复用 `engine.document` 的文档、边和引用契约，剔除前端选择态、测量尺寸等临时信息。`revision`、工作流 ID 和业务版本分别处理。

对象缺少字段与显式 `null` 分别表示，`0`、`false`、空数组和空字符串原样保留。边采用规范化的端点、句柄、槽位和类型识别，数据引用与对应边作为同一变更组。普通列表第一阶段按整个字段处理，避免按下标合并产生错位。

### 两次三方合并

先处理服务端修订变化，再处理 AI 方案与本地编辑变化。

- `S0` 为客户端已知的保存版本，`S` 为当前服务端保存版本，`L` 为客户端最新草稿。
- `B` 为该卡片生成时的有效草稿，`P` 为 AI 候选文档。
- 先计算 `D = merge(S0, L, S)`，再计算 `M = merge(B, P, D)`。

单次合并的逐字段规则如下。

| 变化关系                               | 合并结果                 |
| -------------------------------------- | ------------------------ |
| 只有一方修改字段                       | 采用该方的修改           |
| 两方得到相同值                         | 采用共同结果             |
| 两方修改同一字段为不同值               | 返回字段冲突及三个实际值 |
| 一方删除节点，另一方修改节点或相关引用 | 返回依赖冲突             |
| 一方替换父对象，另一方修改其子字段     | 返回重叠路径冲突         |
| 两方新增相同节点 ID 或争用同一输入     | 返回节点或连接冲突       |

拖动位置与更改代码位于独立字段，可以合并。新增或删除连接后重新计算引用、执行依赖和类型校验。结构冲突解决后，再执行当前执行专家可用性、完整文档、选区范围及循环校验。

选区校验以合并前的最新草稿和原请求选区为依据。用户在选区外的手工修改已经属于最新草稿，AI 的新增差异接受现有 `selection_errors` 检查。准备过程返回结构化冲突与诊断，冲突解决结果须重新经过完整准备。

### 准备与保存

`prepare` 读取最新草稿，执行合并、凭据恢复及所有校验，产生准备 ID。准备记录绑定作用域、动作版本、输入草稿指纹、当前保存修订及最终候选指纹。

用户确认展示的合并差异后，`apply` 使用准备 ID 和幂等键保存。在同一 SQLite 事务内比较服务端修订与动作状态，写入新工作流版本、操作结果、会话操作事件和请求回执。新修订和聊天中的“已应用”具有同一个提交结果。

同一请求重复到达时返回原回执。同一动作的成功保存关联唯一修订，后续请求返回其实际结果。服务端修订再次变化时返回 `SAVED_REVISION_CHANGED`，界面重新准备。

前端发送应用前检查本地草稿序号。应用请求期间暂时锁定改图操作，输入框仍可编辑。超时或断线后重新查询回执和当前保存状态，保留期间产生的新草稿。迟到结果只有在作用域、访问 ID 和草稿序号仍匹配时安装到画布。

### 回退

聊天中的“回退此修改”生成关联原动作的逆向卡片，对当前草稿执行相同的合并、准备和应用。用户后续独立修改可保留，重叠字段进入冲突处理。确认保存后新增修订，并关联原动作及回退动作。

若后来已有修改覆盖了原动作，历史显示原动作及其修订，当前适用状态通过最新草稿检查得出。查看历史消息本身保持只读。

新路由均位于 `/api/flowforge`，所有资源读取、事件订阅和写入均检查账户、工作流及会话归属。涉及目录、方案及运行的操作还校验其执行专家上下文。专用专家身份通过服务端绑定解析。

| 方法与路径                                   | 请求和返回要点                                         |
| -------------------------------------------- | ------------------------------------------------------ |
| `GET /authoring/assistant`                   | 返回专用专家绑定、显示名称、知识包版本和可用状态       |
| `GET /flows/{flow_id}/authoring/experiences` | 分页读取当前账户在该流程的问题、尝试、验证和经验       |
| `PATCH /authoring/experiences/{id}`          | 带版本编辑总结、纠正判断或标记失效，保留实际运行来源   |

发送消息的主要请求字段如下。

```json
{
  "client_request_id": "uuid",
  "expected_last_message_seq": 12,
  "mode": "auto",
  "text": "改一下，空值也处理",
  "context": {
    "draft": {},
    "execution_agent_id": "default",
    "saved_revision": 6,
    "draft_owner_id": "browser-visit-uuid",
    "draft_sequence": 24,
    "selected_node_ids": ["compute"],
    "source_action_id": null,
    "repair_source": {
      "run_id": "recorded-run-id",
      "node_id": "compute"
    }
  }
}
```

`draft` 使用完整 `FlowDocument`，示例中的空对象仅表示字段位置。`repair_source`、方案引用和选区均为可选输入。请求体的账户和日志内容由服务端的身份及真实运行记录取代。

SSE 事件包含单调递增的事件序号、会话 ID、轮次 ID 和类型，客户端按事件身份去重。主要类型为 `turn.accepted`、`context.updated`、`turn.phase`、`message.delta`、`tool.updated`、`message.completed`、`action.ready`、`action.applied`、`verification.updated`、`experience.updated`、`turn.failed`、`turn.cancelled` 和 `resync.required`。

订阅使用携带宿主认证头的 fetch 流。断开订阅只释放连接，停止操作调用取消接口。取消与完成竞态由服务端终态比较并交换决定，完成事务已提交时返回完成结果。插件卸载等待模型任务取消和状态落盘，重载后的查询恢复已提交数据。

错误响应使用 `code, message, retryable, details`，前端按代码处理。主要代码包括 `TURN_IN_PROGRESS`、`CONVERSATION_ADVANCED`、`IDEMPOTENCY_MISMATCH`、`DRAFT_CONFLICT`、`SAVED_REVISION_CHANGED`、`PREPARATION_EXPIRED`、`SCOPE_CHANGED`、`MODEL_UNAVAILABLE` 和 `VERIFICATION_INPUTS_INCOMPLETE`。

`409` 承载并发、准备过期及需要合并的状态，`422` 承载字段、结构和来源校验错误，`503` 承载模型暂不可用。身份认证沿用宿主响应，资源查询根据实际归属返回可读数据或资源错误。

## 验证运行的实现

验证计划复用 `start_debug_run`、`prepare_debug_plan`、持久化运行记录和现有事件流。计划绑定已应用修订、源运行、目标节点、输入及依赖指纹，开始时重新检查。

默认验证目标节点。当前修订提供代码、提示词、超时和其他配置，源运行提供可用的业务输入及上游成功输出。历史输出经槽位、类型和节点身份检查后作为 `pins` 交给调试入口。

原始 `node_details.inputs` 同时可能包含业务输入和脚本源码等配置。计划按真实连接及字段来源组装可复用数据，代码、提示词及最新修复字段读取当前修订。将历史输入整体覆盖目标节点会覆盖修复后的源码，这一场景需要独立回归。

历史数据缺失、绑定路径变化或输出与当前槽位不兼容时，计划展示具体缺失项，用户补充测试值或选择执行到目标节点。历史记录中已脱敏的占位文本只能用于展示，真实复用值从服务端原始记录取得，并受当前账户、工作流及执行专家作用域校验。

验证请求先在 SQLite 中保留幂等记录与预分配运行 ID，再通过服务端内部参数交给运行生命周期。运行初始记录包含会话、卡片、源运行和目标修订，业务节点在该记录完成落盘后入队。HTTP 重试读取原验证请求及运行 ID。

SQLite 与 JSON 运行记录之间采用可核对的启动状态。进程在启动窗口中断时，恢复流程先按预分配 ID 查询原运行并修复关联。执行状态无法确定的任务显示中断及重试入口，新的执行由用户发起并创建新验证记录。已存在运行继续沿既有取消、暂停、审核及恢复生命周期。

运行卡片显示实际执行范围。单节点通过表示该节点验证通过，整流程通过由实际整流程运行结果记录。卡片保留零值、布尔值、空值、实际错误与缺失标记，并可打开完整运行观察。

## 前端状态与组件

前端将服务端会话状态和当前浏览器编辑访问共同用于判断响应归属。

```typescript
interface ConversationView {
  conversationId: string;
  authoringAgentId: string;
  scopeKey: string;
  visitId: string;
  lastEventSeq: number;
  activeTurnId: string | null;
  selectedActionId: string | null;
  composerText: string;
}

interface EditorContext {
  executionAgentId: string;
  draftOwnerId: string;
  draftSequence: number;
  savedRevision: number;
  draft: FlowDocument;
}
```

`useAuthoringConversation` 取代现有会话 hook 中的纯内存轮次管理，负责分页、发送、事件恢复、取消和卡片状态。编辑器保留草稿、保存和撤销历史的所有权，新 hook 通过受检查的回调读取当前文档并提交已经准备的结果。

聊天栏分为 `ConversationPanel`、`MessageList`、`Composer`、`ChangeCard`、`ConflictCard` 和 `VerificationCard`。优先复用现有运行值展示、差异预览、结构诊断和宿主组件，组件按交互职责拆分。

聊天消息和卡片状态保存在服务端。本地只保存会话引用、未发送文字、栏宽、消息阅读位置和当前浏览器草稿。作用域确认前暂缓恢复缓存，服务端保存失败时输入内容继续可见。

轮次状态使用 `queued → running → completed / failed / cancelled / interrupted`。卡片记录 `proposed / applied / discarded / reverted`。是否需要重新准备、是否存在冲突由当前草稿计算，两个标签页可看到同一卡片在各自草稿中的适用状态。

## 迁移与实施顺序

### 第一阶段完成持续讨论和修改

配置工作流助手及版本化知识包，接通正常专家运行时、工作流工具、持久宿主会话映射和作用域明确的经验检索。实现消息、动作及轮次服务，接入自然答复、澄清和修改卡片。将历史恢复、应用后续聊、最新草稿合并、冲突处理、调试问题记录、停靠聊天栏、停止及断线恢复一起作为可交付版本。

新 UI 默认接入会话接口。升级时当前内存会话如果仍存在，可通过带原提案引用的幂等导入转换为消息和卡片，保留服务器仍持有的原始要求与变更。完整历史缺失时以实际可读的记录建立历史来源，应用新修改时根据最新草稿重新检查。

### 第二阶段接通修复验证

实现验证计划、幂等启动和运行卡片，完成“解释失败 → 修复 → 应用 → 同输入验证 → 继续修复 → 经验更新”的实际入口验收。将验证通过的修复提炼成带版本及适用条件的通用经验，并通过专用记忆后端投入后续工作流使用。

每阶段实现时同步 canonical、分发副本与构建产物，沿用插件版本与发布流程。设计稿中的原型使用示例状态，功能交付以真实接口和运行验收为准。

## 设计依据

当前实现的纯内存会话、父方案和应用后重置位于 `ui/src/useAuthoringSession.ts`，界面位于 `ui/src/AuthoringPanel.tsx`。持久版本和限时提案位于 `flow_repository.py`。模型适配、真实调试和公开运行观察分别位于 `engine/adapter/llm_service.py`、`debugging.py`、`lifecycle.py` 及 `inspection.py`。

专用专家接入依据为 `runtime/builder.py` 的专家组装与技能注入、工作区 `stream_query`、`app/chats/session.py` 的持久会话，以及 `plugins/memory.py` 的 `MemoryBackend` 接口。现有工作流节点适配器的随机会话行为位于 `engine/adapter/agent_runtime.py`，持续编辑桥接需覆盖该会话语义。

Make Maia 提供计划与构建模式、按流程续聊、聊天中的版本回退和可管理记忆，可借鉴会话恢复和版本关联。[Make 官方说明](https://help.make.com/introduction-to-maia-by-make)

n8n Assistant 将构建、运行、读取错误和再次修复连接在同一操作流程中，可借鉴修复后的验证入口。[n8n 官方说明](https://blog.n8n.io/introducing-n8n-assistant/)

Zapier Copilot 在同一会话提供解释、建议、修改和检查点，可借鉴自然讨论及可回退操作。[Zapier 官方说明](https://help.zapier.com/hc/en-us/articles/45327353705997-Best-practices-for-using-Zapier-Copilot)
