# 右侧工作区与上游融合约定

本次对照本地 `upstream/main` 的原生文件工作区，保留 `filesSurfaceStore`、会话 scope、`FilesWorkspace`、`TabbedEditor` 和原生文件 API 主链路。UGSci 面板不另建文件树、编辑缓冲、差异状态或保存协议。

## 扩展边界

- `FilesDrawer` 负责原生抽屉、宽度、焦点、预览／工作区切换；工作台模式由 `WorkbenchExtensions` 的类型化面板定义适配。新增面板应在此边界接入，避免不断向抽屉和聊天主页面增加分支。
- `useWorkbenchRequests` 将既有 reveal、compute、simulation 事件转换为原生抽屉事件，统一验证活动页面、Agent、Chat 和运行时会话身份；旧的无 scope 事件继续兼容。原生文件预览事件仍由聊天宿主处理。
- `WorkbenchPanels` 保留既有插件 Slot 和运行中心公开能力的适配，不要求已经发布的插件更换协议。GenUI 文件展示经过 `FilePreview`，与文件标签使用同一渲染器注册表。
- 文件标签与未保存内容保留在原生 store。浏览器只在首次打开后保留 iframe 和地址草稿；会话切换或关闭抽屉释放实例。带轮询／GPU 的扩展面板隐藏时卸载，重新进入时从持久数据恢复。隐藏文件区暂停重型预览，避免同一个 GenUI 目标同时创建两个渲染实例。
- 预览错误在统一预览入口隔离；失败不应破坏聊天、文件导航或文本编辑。专业格式插件失效时保留宿主提供的兜底。

## 原生行为契约

1. Markdown 使用上游公式处理和 `RenderableCodeBlock`；保留公式、Mermaid 的预览／源码切换及复制下载，保留鉴权相对资源和文件链接。原生支持的图片格式（包括 ICO）继续可预览。
2. 文件根目录、会话和 Agent 身份贯穿读取、下载、保存；多目录同名文件不能共用缓冲。文件大小使用实际加载结果，恢复标签和刷新时同步更新。
3. 显式文本打开意图传入原生标签。不同生成产物以稳定产物 ID 或 URL 区分，显示名不充当唯一身份。
4. 生成文本另存复用会话作用域的原生上传接口，写入真实字节，以自动重命名处理重名，打开服务端返回的真实路径。取消和失败不能标记保存成功，迟到响应不能切走用户后来选择的标签或写入另一会话的 UI。
5. SDK 流式产物更新必须同步到宿主文件状态，使预览、复制、下载、另存内容一致；用户未保存编辑和待审阅 diff 不能被后台更新覆盖。
6. 关闭最后一个标签时清空文件标题及引用目标。预览加载失败仍可展开工作区。窄屏预览不能切入一个已经隐藏的导航区域。

## 后续上游更新的验证

先合入原生文件行为，再复核这些扩展边界；不要用替换整个上游文件组件或减弱测试断言解决冲突。`console/scripts/verify-fork-features.mjs` 同时登记真实聊天宿主、抽屉、文件／编辑器、原生渲染器和自有插件用例。

执行 `cd console && npm run test:fork-features`、`npx tsc -b --noEmit` 和 `python scripts/verify_fork_regressions.py`。重构后构建前端，并通过真实页面检查预览／编辑往返、公式和代码块控制、宽窄窗口、会话切换、插件卸载及保存结果。

单元和集成测试使用合成数据，不能替代商业数模文件、大型工程、真实外部网站嵌入或桌面安装包验收。扩展边界能减少上游合并的修改面，但不代表未来更新无需审阅或永远没有冲突。
