# 工作区终端与侧边聊天设计

2026-11-10。终端为本轮接入范围；侧边聊天为可交互设计，尚未连接模型和真实会话。

## 入口与布局

新标签页的工具区保持两列，顺序为“打开文件 / 新建网页”“终端 / 侧边聊天”“任务交互 / 智能体进程”。常用视图、当前会话后台事项与最近关闭继续使用实际数据。所有入口与既有按钮共用尺寸、圆角、图标和主题。

推荐默认采用**旁聊标签**：侧边聊天与文件、网页、终端一样，是右侧工作区的一种内容标签；主对话继续在左侧工作。工作区较窄时，这种方式保留可读宽度。展开工作区后可采用**内容分屏**：文件、网页或终端居左，旁聊居右，右栏建议初始 320px，可调整。小于 540px 时只显示当前内容或旁聊，提供明确的切换入口，不压缩成两条窄列。

可交互布局稿提供“旁聊标签”“内容分屏”两种方案，可以切换新标签页、终端和旁聊，试写独立草稿，在展开方案中切换文件与终端、收起旁聊。它只验证布局和本地交互，不产生模型请求。

## 终端接入

复用现有 `TerminalDock` 会话面板、`TerminalView`、`terminalApi` 与后端 PTY 服务。工作区中新增终端内容类型，不增加另一套执行协议。一个工作区终端标签可管理当前会话的多个终端进程。新建进程按现有服务解析的会话目录启动，重命名、重启、退出状态、输入分片和尺寸调整继续走原有逻辑。

顶部关闭终端**视图**保留服务端进程；终端内部的关闭操作结束指定进程。切换文件等内容时停止隐藏终端的输出轮询和尺寸更新，回到终端后读取服务端保留输出。底部面板和工作区使用同一组终端，只有一个表面负责终端 I/O：选择工作区终端时收起底部面板；随后显式打开底部面板时，工作区显示“终端已在底部面板打开 / 移至工作区”。

保留后端认证与能力检查。当前开发服务的 `/api/terminals/status` 返回 `enabled: false`，源码表明是认证开关未启用。界面应展示既有启用认证、重启并登录的说明，不发送创建进程请求。依赖缺失和暂时无法访问分别显示对应状态。

## 旁聊的会话语义

- 打开旁聊先创建本地草稿视图，首次发送才创建实际旁聊会话。
- 旁聊拥有独立会话身份、草稿、消息队列、流式状态与停止操作，关联发起它的专家和主会话。
- 创建时继承主会话已完成的上下文快照。正在生成或尚未返回的工具调用以明确的未完成引用表示，不伪造成功结果，也不重复执行继承的工具调用。
- 文件、网页与终端选择片段以可移除的引用显示在输入框上方。引用携带来源、作用域和范围，发送前可以看见实际要带入的内容。
- 默认采用主对话创建时的模型配置，可为旁聊单独选择模型；后续切换主对话模型不会隐式改写正在运行的旁聊。
- 关闭标签保留旁聊及草稿；停止生成是单独操作。恢复标签时连接原会话，避免再次发送首条问题。
- “转为独立对话”将其显示在现有会话列表并保留历史。父会话切换、迁移、删除的行为应有明确回归，避免旁聊出现在另一位专家或另一段主对话中。

## 技术可行性与边界

现有工作区通过 `WorkbenchMode`、`WorkbenchPanelContext`、`WorkbenchContentPanel` 和 `workbenchTabsStore` 承载不同内容，能够新增终端或旁聊适配面板。文件缓冲区继续由原生编辑器管理；旁聊标签只保存子会话引用和视图信息。

现有聊天页面已经具备模型、草稿、队列与流式渲染能力，但不能简单地在右侧再次挂载完整 `ChatPage`，因为页面还负责路由、当前可见会话、终端和文件面板。正式实现旁聊应提取可独立挂载的会话表面，以独立 owner/session 接入 SDK 和现有队列，保留实际页面上的 @ Agent、直接指派、共同协作、消息排队、文件预览和交互表单行为。

后端已有 `parent_session_id` 关系以及 `/fork/agent` 的子代理分叉逻辑；后者为工具层子代理准备会话，并可能创建 Git worktree，不能直接当作旁聊 API。正式旁聊需要面向用户会话的创建、上下文快照、恢复与转独立接口，并明确普通会话列表中的展示规则。具体接口与测试属于后续旁聊实现范围，本轮不假定已具备这些能力。
