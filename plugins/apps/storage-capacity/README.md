# 库容评估工作台

面向周期评估、阶段标定与设计复核的 PawApp。入口 `/apps/storage-capacity`，应用版本 0.3.0，计算数据格式 v2。界面使用宿主 React、认证请求与智能体上下文，采用与 QwenPaw Data、文书填报应用一致的项目导航、表单、表格及分步工作区。

## 工作流程

1. 建立项目，明确建库类型、周期、起止状态、压力口径及气量标准状态；按连通区、层系或盐穴划分单元。
2. 上传资料，检查提取内容；选择工作表、表头、行范围、字段与换算倍数后应用。原件、SHA-256、原始值和单元格位置保留在项目资料库。
3. 为每个单元选择方法并确认条件。补充计量、压力、PVT、拟合、采气预测或真实外部成果；运行确定性计算。
4. 查看未满足条件、分单元公式、残差、敏感性和交叉校验。需要工程判断时，显式调用已有 `Inventory-agent` 进行方法审查。
5. 导出 Word、可打印 HTML 或复算 ZIP。报告绑定输入指纹；资料、参数或意见变化后必须重新计算。项目及计算快照按登录用户与当前智能体隔离持久保存。

## 方法与边界

| 方法 | 适用前提 | 本应用完成的计算 |
|---|---|---|
| 两点 p/Z | 同一连续采气段、无注气、定容近似、单气相或油环影响可忽略、无水侵或已论证可忽略的弱水侵 | 起始有效库存、下限可动垫气、地层调峰气量、可选压力窗口工作气量、单因素敏感性 |
| 多点 p/Z | 至少 3 个不同累采量点，从本采气段零值开始，压力具有代表性 | 最小二乘拟合、残差、R²、RMSE、库存及压力窗口指标 |
| 已知水侵量的气相物质平衡 | 同状态体积系数与独立水侵/产水量，气相定孔隙体积近似 | 体积守恒求有效库存；不求解水体模型、组分传质或凝析 |
| 体积与压力窗口 | 净含气体积、绝压、绝温、标准状态和 Z 有依据 | 上限库容量、下限气量、工作气量；仅为筛选，不证明完整性及注采能力 |
| 数值模拟成果复核 | 真实软件、模型/输入版本、运行编号、同周期同状态指标和历史拟合记录 | 成果一致性、RMSE、MAE、同口径汇总；不声称运行了模拟器 |
| RTA 成果复核 | 真实解释成果、弱干扰、不重叠井控范围 | 同上；不以简单线性拟合冒充 RTA 专业求解器 |

补充算法包括测压加权、PVT 有界线性插值、二项式单井产能、分段平均日量积分、地面处理限额、计量平衡、设计指标及同周期成果偏差。全库综合调峰计算考虑统一采气期、共用设施和各单元剩余可采气量；资料不足时仅保留分单元结果。声明地面设施与外输通道完全独立后，才允许按独立成果相加。

压力、Z、采气量差值接近不稳定区间时阻断或提示。缺测不是零；负的账面减有效库存差值保留并提示，不能直接认定损耗。R²、撤采比例、对比偏差是明确标注的工程提示，不伪装成行业验收线。预测积分不能用“冲峰量 × 天数”替代。

## 标准与术语

参考本机 UGSci 库存评价智能体所定义的工作边界。标准依据是 **SY/T 7686-2023《储气库库存评价技术规范》**。已通过国家标准信息公共服务平台核实目录、名称与实施日期；未取得的完整条文不编造条款号，也不声称通过标准符合性签审。天然气损耗规范另列为 SY/T 7759-2024，不与未动用库存混同。

库存量、有效库存、可动垫气、工作气量、地层调峰气量、综合调峰能力和冲峰能力分别输出。采用同一报告的气量口径可做带警示的物质平衡条件复算；体积状态方程及跨来源气量比较仍需明确标准温压。

目录链接：https://std.samr.gov.cn/hb/search/stdHBDetailed?id=016FDF2BE00B8559E06397BE0A0AD220

## 数据、智能体和报告

后端：`catalog.py` 定义方法与术语；`intake.py` 负责原件提取/显式映射；`methods.py` 为纯算法；`workbench.py` 处理适用性、质量及全库汇总；`service.py` 提供持久项目 API；`reports.py` 生成一致的报告视图。

用户数据保存在宿主工作目录 `apps/storage-capacity/<scope>/<case>/`。保存检查 revision，计算结果写入独立 run 文件；过期结果不能导出。JSON 只能导入参数，不能伪造服务端资料索引或已完成计算。切换宿主智能体会重置前端项目上下文。

`POST /api/storage-capacity/cases/{id}/review` 仅在用户点击“方法审查”时调用既有 `Inventory-agent`；算法事实作为只读输入，智能体负责适用性、缺项和差异解释。不可用时返回明确错误，仍可计算及导出。不会生成虚构的专家执行轨迹、置信区间或批准结论。

支持 XLSX、CSV/TSV、PPTX、PDF、DOCX、JSON、文本。扫描图及图片公式不自动猜读；PPT 按演示顺序而非文件名标页码。XLSX 使用已保存公式缓存，空缓存保持缺失。插件声明 openpyxl、pypdf、python-docx 依赖，可由宿主依赖修复入口安装；不在页面静默安装依赖。

报告含范围、标准与假设、主要指标、来源摘要、质量检查、分单元公式和参数、拟合/敏感性、交叉校验、历史成果及复核意见。复算包保存参数和计算快照，不重复打包原件；原件可单独下载并按摘要核对。

## 0.3.0 流程工作台

左侧为十二个竖向流程节点，中间显示当前单元的参数、资料与独立结果；右侧评估助手可拖动调宽、键盘调宽及收起。新建项目支持建库类型、岩性、储集空间、运行阶段、方法偏好，也可留给后续资料判断。

参数传递：原始压力/解释压力 → 统一绝压和基准面 → 单元加权代表压力 → 同温 PVT 表插值 → 有效库存 → 压力窗口 → 产能和调峰预测。每一步仍可独立录入已核实输入并运行，不强制先运行前一步。修改输入后按节点、单元指纹标记旧成果；整份报告必须重新计算。

- 压力节点保留原测压、解释压力、关井时间、深度、权重与依据。基准面修正使用已知梯度，不自动把短关井值解释成平衡压力。
- PVT 节点提供实验表有界插值和 Bg 状态换算；检查温度与 P/Z 口径，不外推、不代替组分 EOS。
- 连通性节点计算同步等间隔压力序列的滞后相关性，支持差分；相关性只作响应诊断，单元划分仍需地质与试井解释。盐穴分支不强套井间相关诊断。
- 日步长预测耦合库存、P/Z 压力和固定井底压力二项式产能，受地面上限、下限压力、剩余可采量约束；属于筛选模型，不替代井筒管网模拟。
- 对话通过实际 Inventory-agent 读取所选资料。空值的直接摘录可自动填写，冲突取值、类型和方法判断先列候选；所有采纳保留原文、文件位置，支持撤销最近一次填写。无证据或超出字段范围的建议被拒绝。纯数值仍交给确定性算法。
- 对话和人工修改均检查 revision；慢回复不能覆盖新版本。报告增加节点输入指纹、结果、过程数据和字段取值来源；完整节点数据在复算包中保留。

新增 API：`GET /cases/{id}/workflow`、`POST /cases/{id}/nodes/{node}/run`、`POST /cases/{id}/assistant`、`POST /cases/{id}/assistant/adopt`、`POST /cases/{id}/assistant/undo`，路径前缀均为 `/api/storage-capacity`。

新增回归 `tests/unit/plugins/test_storage_capacity_flow.py`，覆盖独立节点、跨单元失效隔离、PVT/测压口径、连通响应、动态预测守恒、真实 DOCX 输出、字段证据校验、候选采用、撤销和并发保护。前端固定清单增加独立节点、助手调宽/收起/撤销、附件先上传再提交对话的实际挂载测试。

## 节点图表与结果工作区

各节点通过“参数资料 / 图表结果”页签分开编辑和查看成果。运行本节点后进入图表结果；从图表打开独立视窗后返回参数资料，便于边编辑边对照。切换页签不重置未保存输入和已打开的窗口。范围、资料、方法与归档以清单表呈现；PVT 展示压力—Z 和压力—Bg；地层压力对照实测、修正及代表值；连通性展示同步响应与滞后相关；有效库存展示 p/Z 关系、拟合残差、敏感性及外部历史拟合；压力窗口对照压力边界和气量；调峰分图展示时间—流量、压力、累计采气；整库指标按量纲分组，并可查看历史周期。图表参考呼图壁、相国寺、板中北等课件的展示关系，引用标在对应图表说明中。

点击“在结果视窗打开”将图表固定到中部下方的结果工作区，跨节点、跨单元可同时打开最多 12 个窗口。窗口可拖动标题栏、拖动右下角缩放，也可用方向键移动或缩放（Shift 加大步长）；支持平铺、层叠、最小化、最大化、关闭。工作区高度可拖动调整，也可放大占满中部，再返回表单布局；右侧助手仍可独立收起。窗口仅在当前项目页面会话保留，切换项目清空窗口。

每个窗口保留打开时的资料或计算快照，输入修改后提示历史状态，重算后可另开窗口进行版本对照。服务端节点成果保存 `chart_context`，绑定当时的项目口径和单元输入，避免旧结果与新参数混绘。图表可切换数据表、显示/隐藏系列、导出 CSV 或含标题和图例的 SVG。缺测值不补零；预览数据不作为计算结论；未提供井位坐标、数模网格或真实外部成果时不生成压力场、模型云图或虚构拟合。

前端页面行为回归覆盖多窗口快照、移动缩放、平铺、最小化恢复、放大工作区、跨项目清理、缺测断点和系列切换；后端回归验证原始输入改变后旧图表数据与结果指纹保持一致。
