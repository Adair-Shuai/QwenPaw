# 文书填报

UGSci 独立应用，地址 `/apps/document-forms`。从 Excel 读取变量配置，显示填写表单，核对后按 Word 模板生成文件。无需配置模型。

## 使用

1. 新建填报，选择 Excel 变量管理表。
2. 添加配套 Word 模板，修改共用资料与受邀单位，保存草稿。
3. 进入核对页，处理缺项、未知变量和日期冲突。核实共用信息与输出清单后勾选确认。
4. 生成并逐份预览；可单独下载 Word，或下载包含 Word、填写数据及核对记录的整包。

填写页从上到下排列资料、受邀单位和 Word 模板，核对入口位于页面末尾。研究内容、成果与考核等长段落使用通栏文本框并随内容增高；核对页保留完整换行，确认按钮位于信息与输出清单之后。

原对话中的业务模板需由用户导入。应用提供的“入门模板”只是变量管理表、谈判文件和邀请函的通用示例，不包含原文书的业务条款。支持 `.xlsx` 与 `.docx`；旧 `.xls`、`.doc` 请先在 Office 中另存为对应格式。单个文件上限 15 MB。

## Excel 约定

“变量配置”工作表首行：`变量名称`、`中文名称`、`值`。变量名称支持 `project.name` 这样的点分层级，三列顺序可以调整。编号、电话等需要保留前导零时，应在 Excel 中保存为文本。

可增加三列：

| 列 | 含义 |
| --- | --- |
| 分组 | 表单中显示的分组名称 |
| 类型 | `text`、`textarea`、`date`、`datetime-local`、`number`；省略时按字段和内容推断 |
| 必填 | 默认“是”，填“否”可允许留空 |

“受邀单位”工作表首行：`单位名称`、`领取开始时间`、`领取结束时间`。可增加或移除单位。时间支持 Excel 日期单元格、ISO 日期时间和常见中文日期，导入后转换为日期控件。

兼容未写入行列范围的 Excel，以及带括号说明的表头，例如“受邀单位（invitation.recipient）”“邀请函领取开始（YYYY-MM-DD HH:MM）”。编号为空白单位预留的行会保留供补充，表后的说明行不会成为单位。

“校核规则”工作表可选，首行：`校核项`、`开始变量`、`结束变量`、`允许相同`。起止列引用变量名称；允许相同默认“是”，填“否”时要求严格先后。应用自动检查常见发文、答疑、响应截止及谈判日期，核对各单位领取时间。`dates.issue` 为共用落款；如同时配置 `dates.invitation_issue`，要求两者一致。业务日期检查是完整性与先后关系检查，不代替采购规则审核。

“日期校核”中的既有结果及公式缓存不用于放行生成。每次核对均依据当前表单值计算。导出 Excel 包含当前填写值、单位、规则及本次检查快照；继续修改 Excel 后应重新导入核对。

发放、答疑及谈判时段支持完整起止时间，例如 `2026-07-25 14:30 ~ 2026-07-25 17:30`。表单保留原文，校核会比较时段内部顺序、前项结束与后项开始，以及各单位领取时间是否落在总体发放期内。响应截止必须早于谈判开始。

输入变量、受邀单位和规则中的公式会提示改为明确值，避免将缓存值当作新数据。原 Excel 的其他工作表及样式不随导出复制；原文件不会被修改。

## Word 约定

共用变量：`{{ project.name }}`、`{{ dates.issue }}` 等。支持段落、表格、页眉页脚及被 Word 拆为多个文字样式段的占位符，使用 docxtpl 保留模板原有版式。

邀请函可使用 `{{ invitation.recipient }}`，或 `{{ invitation.start }}` / `{{ invitation.end }}`。包含这些变量的模板按受邀单位分别生成，其余模板生成一份。邀请函中的 `{{ events.invitation_time }}` 使用该单位的领取时段；共用文件中的同名变量使用 Excel 配置的总体发放时段。若 Excel 未配置该变量，仅使用它的旧式模板仍按单位生成。项目及落款继续共用。生成时日期时间中的 `T` 显示为空格。

模板变量需与 Excel 配置相符；未配置变量、漏填及日期冲突均阻止生成。使用受限 Jinja 环境，不支持函数调用或下标取值。图片占位符、循环明细表、复杂宏不属于当前输入约定。

## 保存与兼容

草稿保存于宿主工作目录的 `apps/document-forms`，按登录用户和 Agent 隔离。点击保存、导出、核对或添加模板会保存当前修改。每次生成保留独立批次，修改后旧批次标明过期；生成失败不会留下半批成功文件。并发页面修改通过修订号检测冲突。

前端优先通过宿主 `workspace.loadPreview()` 嵌入现有 `ArtifactPreview` / Office 渲染链路。已发布宿主尚未提供该接口时，通过同一 `/workspace/convert-office` 服务在应用内预览，可单独安装应用使用。预览保真程度沿用宿主 OfficeCLI / 兼容渲染能力。

## 开发验证

```text
node plugins/apps/document-forms/build.mjs
python -m pytest plugins/apps/document-forms/tests/test_document_forms.py -q
cd console
npm run test:fork-features
npx tsc -b --noEmit
```

页面集成回归加载实际 `ui/index.js`，验证宿主内嵌 Office 组件以及已发布宿主的共用转换服务；后端回归读取真实 XLSX/DOCX，检验三家单位分别生成、统一落款、格式与转义、日期冲突、作用域隔离、确认失效及原子生成。

独立发布流程为 `document-forms-release.yml`。测试与可重复构建检查通过后，使用仓库已有插件打包器生成此应用的安装包，校验远端内容后登记市场目录，保留其他应用与历史版本。版本化安装包发布后不覆盖。
