# 智能体与工作流双向调用

## 使用

在智能体的工具配置中启用所需的 `flowforge_*` 工具（沿用插件工具默认关闭的约定）。工作流仍在现有画布中保存和管理。

1. `flowforge_list_workflows` 查找工作流 ID 和描述。
2. `flowforge_get_workflow(flow_id)` 查看流程定义及输入。
3. `flowforge_run_workflow(flow_id, inputs, wait_seconds)` 启动一次运行。
   等待范围为 0–60 秒，默认立即返回。超时只结束等待，后台运行继续。
4. 使用返回的 `run_id` 调用 `flowforge_get_run`，读取状态、输出和错误；不要因为仍在运行而重复启动。
5. `flowforge_cancel_run` 请求取消运行及其子运行。异步节点会收到取消；阻塞代码或已提交的外部业务动作不能靠取消撤回。

工作流中的 `AgentNode` 使用稳定的 `agent_id`，通过目标工作区的 `stream_query` 运行智能体，使用该智能体已有的运行时和工具配置。每次调用创建独立会话，避免并发节点混用聊天历史。已完成的助手文本作为节点输出传递给下游。查找不到智能体或运行失败时，节点明确失败，不再自动降级成普通 LLM 调用。

## 调用边界

- 同一异步调用链禁止重复进入相同工作流，最多嵌套 8 层；不同工作流之间可以嵌套调用。
- 工具与画布共用服务及持久化运行记录，可在现有运行界面查询。
- SubworkflowNode 也经过同一服务，记录 parent_run_id、root_run_id、触发方式和来源身份。裸执行器没有服务时明确拒绝子流程。
- 子流程等待审核时父流程一起暂停；通过现有恢复接口继续，恢复固定到保存的流程快照。已成功节点不会因这次恢复而重复执行。同一暂停只允许创建一次 continuation，重复请求返回 409。
- 智能体检查点恢复尚未接入宿主接口，会明确报不支持，不会重新聊天来冒充恢复。
- 本轮输出以文本为主，未新增附件、流式工具活动的完整映射。
- 嵌套调用栈会写入运行记录并在恢复时重建，但不是跨进程、外部智能体后端的全局调用预算。
- 本轮未新增工作流级 ACL、发布版本锁定、幂等业务键、审批节点或重试补偿；当前工具访问范围仍与插件的共享流程存储一致，不代表多租户隔离。

## 后续企业落地顺序

1. 工作流发布版本、标准输入输出契约、按智能体授权可调用流程。
2. 业务幂等键、全链路成本预算、任务队列和失败重试策略。
3. 审批权限与待办界面、失败补偿及多进程租约恢复。

回归测试覆盖双向往返、嵌套拒绝、深度限制、真实运行时接口的事件适配、错误传播和等待超时后继续查询。实际模型供应商与外部智能体后端仍需部署环境联调。
