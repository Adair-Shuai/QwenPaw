# UGSci 工具·技能与引擎架构方案

## 1. 背景与目标

UGSci 简洁模式原有“工具”和“技能”两个侧边栏入口。“工具”主要管理 MCP 客户端与仿真软件，“技能”主要管理当前专家加载的技能与共享技能池。对用户而言，它们共同回答的是“当前专家能做什么”，分散入口会增加理解和查找成本。

本次改造目标：

1. 将侧边栏“工具”“技能”合并为“工具·技能”。
2. 建立“工具 / 引擎 / 技能”的统一信息架构，默认直接进入可操作的工具视图。
3. 将“计算引擎”扩展为“引擎”，容纳仿真软件、领域计算和运行服务。
4. 将 QwenPaw 原有 ACP 作为“运行服务”纳入引擎体系。
5. 最大限度复用现有页面、API、缓存、Agent 作用域和原生管理功能，不复制核心配置逻辑。
6. 保留旧路由和完整模式行为，不影响现有核心功能。

## 2. 核心概念

工具、引擎和技能不是互斥分类，而是不同层级：

```text
引擎（计算或执行能力提供者）
  ↓ 暴露
工具（Agent 可调用的标准接口）
  ↓ 被组合
技能（何时、如何组合工具完成任务）
  ↓ 装配到
专家（面向领域任务的执行主体）
```

### 2.1 引擎

引擎是真正提供计算或执行能力的后端。适合定义为引擎的对象通常具备多个相关操作、共享配置或状态、明确输入输出模型、可独立测试升级、可被多个工具和技能复用等特征。

引擎分为：

- **仿真软件**：Eclipse、CMG、tNavigator、COMSOL、OPM Flow 等。
- **领域计算**：PVT、气藏物质平衡、井筒多相流、节点分析、递减分析、经济评价等。
- **运行服务**：ACP 外部 Agent、远程计算服务、HPC 调度、Python/MATLAB 运行时等。

### 2.2 工具

工具是 Agent 实际调用的操作接口。一个引擎可以提供多个工具。例如 PVT 引擎可以提供闪蒸、泡点压力、相包络和黏度计算工具。

“内置”“插件”“MCP”是工具的**来源属性**，不是与引擎互斥的类型。平台未来增加内置 PVT 能力时，可以同时注册为“内置 PVT 引擎”和若干“平台内置工具”。

### 2.3 技能

技能描述何时使用工具、如何校验输入、如何组合步骤以及如何解释输出。技能不承担底层引擎的运行状态和安装配置管理。

### 2.4 专家与市场

- 专家装配工具和技能完成领域任务。
- 市场负责获取新工具、技能、MCP 和专家模板。
- “市场获取 → 工具·技能配置 → 专家·协作使用”构成完整产品闭环。

## 3. 信息架构

简洁模式侧边栏：

```text
专家·协作
工具·技能
市场
```

“工具·技能”页面：

```text
工具·技能
├── 工具
│   ├── MCP 接入
│   └── 平台内置
├── 引擎
│   ├── 仿真软件
│   ├── 领域计算
│   └── 运行服务
└── 技能
    ├── 当前专家
    └── 技能库
```

## 4. 交互原则

### 4.1 合并入口，不混淆对象

工具、引擎和技能共享页面入口、搜索和视觉语言，但保留各自的操作语义：

| 对象 | 主要状态 | 主要操作 |
| --- | --- | --- |
| 工具 | 可用、启用、需配置 | 配置、授权、启停、测试 |
| 引擎 | 已检测、未配置、错误 | 检测、配置、查看版本和任务 |
| 技能 | 已安装、已加载、已启用 | 安装、加载、启停、编辑 |
| 运行服务 | 可用、已启用、运行时异常 | 配置运行时、启停、调用 |

### 4.2 当前专家上下文

页面始终显示当前专家。MCP、技能和 ACP 请求继续传递 `X-Agent-Id`，切换专家时清理 Agent 作用域缓存，防止状态串用。

### 4.3 原生管理边界

UGSci 只做统一导航和页面组合。下列核心功能直接嵌入 QwenPaw 原生页面组件：

- 平台内置工具：嵌入原生 `ToolsPage`，完整保留启停、批量开关、配置、浏览器模式和异步执行。
- MCP：嵌入原生 `MCPPage`，完整保留 Provider 托管服务、JSON/表单创建、OAuth、访问策略和 CRUD。
- ACP Agent：嵌入原生 `ACPPage`，完整保留筛选、创建、编辑、删除、Node 运行时和配置校验。

原生页面通过 QwenPaw Host 的白名单异步加载接口提供，保持代码分包。UGSci 不复制其状态、API、校验或 CRUD，因此原生功能未来升级后，嵌入视图会同步获得升级。

## 5. ACP 作为运行服务

ACP 的本质是为当前专家提供外部 Agent 执行环境，因此归入“引擎 > 运行服务”。UGSci 在该位置直接嵌入完整原生 ACP 管理功能，包括：

- 内置与自定义 runner 筛选。
- runner 的启停、新建、编辑与删除。
- command、args、env、trusted、Tool Parse Mode 和 stdio buffer 配置。
- Node 运行时检测与路径选择。

上述能力均直接运行原生 `ACPPage`；UGSci 只为嵌入模式调整页头、边距和滚动容器。

ACP runner 的 `enabled` 只表示配置已启用，不代表进程或协议健康；真正调用还要求当前专家启用 QwenPaw 内置工具 `delegate_external_agent`。统一页应明确这一前置条件，并提供原生工具管理入口。

## 6. 前端实现方案

### 6.1 组合层

新增统一页面 `ToolsSkillsCenterPage`，它只负责：

- 顶层 Tab 和当前专家上下文。
- 组合现有引擎和技能组件。
- 通过 Host 白名单加载接口嵌入 QwenPaw 原生 MCP、工具和 ACP 页面。

### 6.2 复用项

- MCP：直接复用原生 `MCPPage`，UGSci 不保留独立 MCP CRUD、卡片或 API 适配层。
- 仿真软件：复用 `EngineSection` 及引擎检测、增删改 API。
- 技能：复用 `SkillCenterPage`、`CurrentAgentSkillsTab`、`SkillPoolTab`。
- 平台内置工具：直接复用原生 `ToolsPage`。
- ACP：直接复用原生 `ACPPage`。
- 缓存与认证：复用 `apiFetch`、`clearAgentCache`、Host API Token 和 `X-Agent-Id`。

### 6.3 路由兼容

- 新入口：`/ugsci-tools-skills`
- 旧工具入口：`/ugsci-capabilities`，继续可用并打开统一页工具视图。
- 旧技能入口：`/ugsci-skills`，继续可用并打开统一页技能视图。
- 原生 `/tools`、`/mcp`、`/acp` 路由保持不变。

页面 Tab 使用 `?tab=tools|engines|skills` 表达，可复制和恢复当前视图。历史 `?tab=overview` 自动回落到工具视图。

## 7. 数据模型演进建议

后续可以在后端增加统一引擎描述，但不应阻塞本次前端重构：

```typescript
interface EngineDescriptor {
  id: string;
  name: string;
  category: "simulator" | "domain_compute" | "runtime";
  source: "builtin" | "plugin" | "mcp" | "remote";
  version?: string;
  status: "available" | "unconfigured" | "unavailable" | "error";
  providedTools: string[];
  configuration?: Record<string, unknown>;
}

interface ToolDescriptor {
  id: string;
  name: string;
  source: "builtin" | "plugin" | "mcp";
  providerType?: "engine" | "service" | "runtime";
  providerId?: string;
}
```

领域计算引擎正式实现时，应由引擎注册工具，而不是在前端维护一份重复映射。

## 8. 分阶段计划

### 第一阶段：前端整合

- 合并侧边栏入口。
- 建立工具、引擎、技能三个视图。
- 组合现有引擎和技能组件。
- 将原生 MCP、内置工具和 ACP 完整嵌入统一页面。
- 保留旧路由兼容。

### 第二阶段：统一注册表

- 建立 `EngineDescriptor` 和提供者关系。
- 将领域计算内核注册为引擎并自动暴露工具。
- 引擎注册表增加异常、版本、依赖和工具使用关系。

### 第三阶段：跨类型发现

- 统一搜索工具、引擎和技能。
- 展示“引擎提供哪些工具”“技能依赖哪些工具”“专家装配哪些能力”。
- 增加最近使用、推荐能力和问题处理入口。

## 10. 验收标准

1. 简洁模式只显示一个“工具·技能”入口，不再单独显示 UGSci“工具”和“技能”。
2. 完整模式和 QwenPaw 原生页面不受影响。
3. 旧 UGSci 工具、技能 URL 仍能打开对应内容。
4. MCP 创建、编辑、删除、启停和访问策略功能保持不变。
5. 仿真软件检测、添加、编辑和删除功能保持不变。
6. 当前专家技能、技能库和批量操作保持不变。
7. 平台内置工具完整保留原生启停、批量操作、配置和实验模式功能。
8. ACP 完整保留原生筛选、CRUD、Node 设置和配置校验功能。
9. 切换专家后，MCP、技能、内置工具和 ACP 均显示当前专家数据。
10. Console 与 UGSci UI 均通过 TypeScript 检查和生产构建。
