## 4. 已修复缺陷详情

> 以下缺陷已通过代码审查和测试验证确认修复。保留详情供历史参考。

### BUG-001：仿真工具绕过文件与进程目标治理（P1，已修复）

**修复内容**：
- `plugin.py: _register_simulation_tools()` 为每个工具声明 `tool_type` 和 `target_param`：`launch_simulation` 声明为 `shell` 类型（`target_param="working_dir"`），`edit_simulation_deck` 和 `read_simulation_results`/`analyze_simulation` 声明为 `file` 类型（`target_param="deck_file"` / `"result_file"`），使治理层能执行 Phase 0/1 检查。
- `launcher.py: _ensure_path_in_workspace()` 对 `work_path` 和 `deck_path` 执行 `resolve()` 后的工作区包含关系校验，路径逃逸时抛出 `PermissionError`。

### BUG-002：模拟进程输出较多时发生管道死锁（P1，已修复）

**修复内容**：
- 子进程启动从 `stdout=PIPE, stderr=PIPE` 改为重定向到工作目录中的日志文件（`stdout=log_file, stderr=subprocess.STDOUT`），操作系统负责缓冲管理，不再出现管道满阻塞。
- 日志文件路径为 `<deck_stem>.sim.log`，可用于错误诊断。
- `_monitor_job` 在 `finally` 块中关闭日志文件句柄（存储在 `SimJob._log_file` 上），确保所有退出路径（正常完成、超时 kill、异常）都能释放资源。

### BUG-013：Deck 关键字定位可能误匹配并破坏错误区块（P2，已修复）

**修复内容**：
- 关键字匹配从 `stripped.startswith(keyword_upper)` 改为完整 token 匹配：`stripped.split()[0] == keyword_upper`，`PERMX` 不再误匹配 `PERMX2` 或 `PERMX_EXTRA`。
- `section` 参数从"仅用于文档"改为实际限制搜索范围：定位 section 起止行后，关键字搜索仅在该范围内执行。
- 文件写入从 `Path.write_text()` 改为 `tempfile.mkstemp()` + `os.replace()` 原子替换，写入中断时原文件保持完整。

### BUG-003：前端 GET 缓存跨 Agent 串线（P1，已修复）

**修复内容**：`runtime.ts: buildCacheKey()` 将 `agentId` 纳入缓存键；新增 `clearAgentCache()` 在切换 Agent 时清除旧缓存。

**修复内容**：`runtime.ts: buildCacheKey()` 将 `agentId` 纳入缓存键；新增 `clearAgentCache()` 在切换 Agent 时清除旧缓存。

### BUG-004：自定义专家团配置未传入工作流（P1，已修复）

**修复内容**：`mode.py: _parse_args()` 支持 `@<team_id>` 语法引用自定义团队；`model.ts: registerCustomTeam()` 先注册团队定义再发送 slash command。

### BUG-005：服务重启后专家团 Gate 无法恢复（P1，已修复）

**修复内容**：`gate.py: restore()` 从磁盘 `state.json` 恢复 gate 状态；`mode.py: on_turn_start()` 在每轮开始时检查并触发恢复。

### BUG-006：技能同步覆盖用户同名技能，卸载后造成数据丢失（P1，已修复）

**修复内容**：
- `sync_plugin_skills_to_pool()`：同步前检查目标技能的 `installed_from` 标记，非当前插件的技能跳过同步并记录冲突日志，不再执行 `rmtree` 覆盖。
- `remove_plugin_pool_skills()`：卸载时只删除 `installed_from == source_tag` 的技能；对比 `plugin_install_hash` 与当前 `compute_skill_md_hash()`，用户修改过的技能（hash 不一致）予以保留并降级 manifest 条目。

### BUG-007：重启恢复把所有已死亡 PID 乐观标为 completed（P2，已修复）

**修复内容**：
- 已死亡 PID 的任务状态改为 `interrupted`（而非 `completed`），除非此前 `_monitor_job` 已记录可信的 `returncode`。
- 新增 `is_pid_ours()` 通过 `job.start_ts` 和 `job.deck_file` 校验 PID 是否仍为原始进程，检测 PID 复用场景。

### BUG-008：专家团启动接口不消费 SSE，并且没有绑定新会话（P2，已修复）

**修复内容**：
- `sendTeamMessage()` 先调用 `POST /chats` 创建命名会话，再通过 `POST /console/chat` 发送 slash command。
- 新增 `_consumeSseUntilActivated()` 消费 SSE 响应流，解析 `response`/`content`/`error` 事件，只在工作流激活确认后才显示成功；收到错误事件时抛出异常。
- 返回 `chatId` 供调用方导航到 `/chat/{chatId}`。

### BUG-009：引擎配置存放在插件安装目录，升级时会被删除（P2，已修复）

**修复内容**：
- `_resolve_engines_dir()` 将配置目录从 `PLUGIN_DIR / "engines"` 迁移到 `WORKING_DIR / "ugsci" / "engines"`，与插件安装目录解耦。
- 旧路径 `_LEGACY_ENGINES_DIR` 仅用于向后兼容读取，新写入全部使用新路径。

### BUG-010：任务模板占位符操作实际替换整个模板（P2，已修复）

## 5. 根因归类

这些缺陷主要来自五类架构问题：

1. **插件边界声明不足**：插件工具统一按 internal 注册，没有表达实际副作用和资源目标（BUG-001 已修复——声明 tool_type/target_param + 工作区边界校验）；
2. **前后端契约演进不同步**：专家团前端保留旧编排模型，后端已经切换到 Slash Command 和 Gate（BUG-003 / BUG-004 / BUG-008 已修复）；
3. **运行状态与持久化状态分离**：写入了状态文件，但缺少恢复和进程退出证据（BUG-005 / BUG-007 / BUG-002 已修复——恢复逻辑、进程状态正确性和管道死锁均已解决）；
4. **插件代码与用户数据混放**：引擎配置、技能同步和 bundle 更新没有清晰的数据所有权（BUG-006 / BUG-009 已修复）；
5. **Agent/Workspace 作用域没有贯穿所有层**：缓存键、头像目录和任务存储没有携带正确作用域（BUG-003 / BUG-012 / BUG-010 / BUG-011 已修复）。
