## 概述

专家团是 UGSci 的多智能体协同功能，允许将多个石油领域专家 Agent 组编为团队，以不同模式完成复杂任务。

## 三种编排模式

### 流水线模式 (pipeline)

```
专家 A → (结果传递) → 专家 B → (结果传递) → 专家 C → 综合输出
```

- 步骤依次执行
- 上一步结果作为上下文传递给下一步
- 适用于有明确先后顺序的工作流

**示例**：储层评价团队 — 测井分析师 → 地球物理专家 → 油藏工程师

### 协调者模式 (coordinator)

```
协调者 Agent
  ├── 咨询专家 A → 获取结果
  ├── 咨询专家 B → 获取结果
  └── 综合所有结果 → 输出方案
```

- 由协调者 Agent 主导
- 协调者按需咨询其他专家
- 适用于需要综合判断的复杂任务

**示例**：钻井设计团队 — 钻井工程师协调地球物理专家和采油工程师

### 圆桌讨论模式 (roundtable)

```
        ┌── 专家 A（独立评估）──┐
任务 ──┼── 专家 B（独立评估）──┼── 综合对比 → 最终建议
        └── 专家 C（独立评估）──┘
```

- 各专家独立评估同一任务
- 不传递其他专家的意见
- 最后对比综合
- 适用于需要多视角对比的评审

**示例**：开发方案评审团队 — 油藏/钻井/采油各自独立评估

## 任务发起流程

```
用户点击「发起任务」
    │
    ├── 查找协调者 Agent
    │   └── findAgentIdByName(agents, coordinatorName)
    │       ├── 精确匹配名称
    │       └── 模糊匹配（包含关系）
    │
    ├── 检查任务模板是否有 {占位符}
    │   │
    │   ├── 有占位符 → 打开输入弹窗
    │   │   └── 用户输入具体任务描述
    │   │
    │   └── 无占位符 → 直接发起
    │
    ├── 构建完整消息
    │   └── buildTeamMessage(team)
    │       └── 拼接编排指令 + 任务模板
    │
    ├── 设置选中 Agent
    │   └── host.setSelectedAgent(coordinatorId)
    │
    └── 发送消息
        └── POST /api/console/chat
            headers: X-Agent-Id: <coordinatorId>
            body: { channel, user_id, session_id, input }
    │
    └── 跳转到聊天页 (/chat)
```

### 编排指令

每个专家团包含 `orchestrationPrompt` 字段，这是给协调者 Agent 的系统级指令，告诉它：

1. 使用 `list_agents()` 查看可用专家
2. 按顺序（或独立）向各专家发送 `chat_with_agent` 请求
3. 是否传递上一步结果作为上下文
4. 最终综合所有结果输出报告

## 自定义专家团

用户可通过专家团页面创建自定义团队，保存于浏览器 `localStorage`。

### 数据存储

```typescript
const CUSTOM_TEAMS_STORAGE_KEY = "ugsci_custom_teams";

// 保存
localStorage.setItem(CUSTOM_TEAMS_STORAGE_KEY, JSON.stringify(teams));

// 加载
const teams = JSON.parse(localStorage.getItem(CUSTOM_TEAMS_STORAGE_KEY));
```

> **注意**：自定义团队存储在浏览器本地，不同浏览器/设备间不同步，清除浏览器数据会丢失。

### 团队构建器

`TeamBuilderModal` 组件提供表单：

- **基本信息**：名称、emoji、类别、描述
- **模式选择**：流水线 / 协调者 / 圆桌讨论
- **成员管理**：从 Agent 列表选择成员，分配角色和 emoji
- **协调者**（仅协调者模式）：选择哪个成员作为协调者
- **任务模板**：含 `{占位符}` 的任务模板
- **编排指令**：协调者的系统级指令

### 流程图展示

`TeamFlowDiagram` 组件可视化展示团队执行流程：

- **流水线模式**：线性箭头连接各步骤
- **协调者模式**：协调者在中心，箭头指向各成员
- **圆桌模式**：各成员并列，箭头汇聚到综合节点

## 团队卡片显示

`ExpertTeamCard` 组件展示：

- Emoji + 名称
- 模式标签（颜色编码）：
  - 协调者模式 → 蓝色
  - 流水线模式 → 青色
  - 圆桌讨论 → 紫色
- 成员状态标签：`已找到/总数`（如 `3/3` 或 `2/3`）
- 缺少成员时显示橙色警告标签
- 自定义团队显示金色「自定义」标签和编辑/删除按钮
- 可展开流程图（点击展开/收起）
- 发起任务按钮

## Agent 名称匹配

`findAgentIdByName()` 使用多级模糊匹配：

```typescript
function findAgentIdByName(agents, name): string | null {
  // 1. 精确匹配（含空格处理）
  const exact = agents.find(a =>
    a.name === name || a.name === name.replace(/\s+/g, "")
  );

  // 2. 模糊匹配（包含关系）
  const fuzzy = agents.find(a =>
    a.name.includes(name) ||
    name.includes(a.name) ||
    a.name.replace(/\s+/g, "").includes(name.replace(/\s+/g, ""))
  );

  return exact?.id || fuzzy?.id || null;
}
```

> **提示**：为确保团队正常工作，建议专家名称与 Agent 名称保持一致，或至少包含相同的关键词。

## 添加新预设专家团

在后端 `team/presets.py` 的 `PRESET_UGSCI_TEAMS` 中添加新对象；
前端会通过 `/api/ugsci/team/preset-teams` 自动加载：

```typescript
{
  id: "well-test-team",
  name: "试井分析团队",
  emoji: "📊",
  category: "试井试油",
  mode: "pipeline",
  description: "从压力恢复测试到储层参数解释的完整流程",
  members: [
    { name: "测井分析师", role: "数据预处理与质量控制", emoji: "📡" },
    { name: "油藏工程师", role: "试井解释与储层参数计算", emoji: "🛢️" },
  ],
  taskTemplate:
    "请对以下井进行试井分析：\n井名：{井名}\n测试类型：{测试类型}\n要求：依次咨询测井分析师和油藏工程师。",
  orchestrationPrompt:
    "你是试井分析团队的协调者。请按以下步骤工作：\n1. 用 list_agents() 查看可用专家\n2. 向测井分析师发送数据预处理请求\n3. 将结果传递给油藏工程师进行试井解释\n4. 综合形成试井分析报告",
},
```

> **重要**：`members[].name` 必须与实际创建的 Agent 名称匹配，否则会显示「缺少成员」警告。
