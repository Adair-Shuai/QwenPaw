| --- | --- | --- | --- |
| 本地 Piccolo 决策模型 | 使用独立的分类决策接口，为工具审批、上下文压缩提供判断 | 在模型设置的 QwenPaw Local 中安装支持 Piccolo 的推理引擎，在决策模型组下载并启动模型，再设置默认决策模型；专家安全设置选决策模型审批，或在上下文设置启用决策模型压缩 | 推理引擎必须支持原生决策接口；Flash 与 Piccolo 共用一个托管运行时，启动另一模型会切换当前模型。新增运行时还需纳入 UGSci 下载镜像的发布验收 |
| 本地模型下载源选择 | 在 Hugging Face 与 ModelScope 之间选择模型来源，并安装、更新托管推理引擎 | 国内环境优先尝试 ModelScope；已有模型与推理引擎分别管理，避免更新引擎时重新下载模型 | 下载和实际推理性能需要在目标机器验证；界面内存门槛是目录策略，不是峰值内存承诺 |

| OpenViking 长期记忆插件 | 在模型调用前召回相关长期记忆，在对话完成后向独立记忆服务提交消息，并提供 memory_search | 有集中知识与跨会话记忆需求时，部署 OpenViking，安装插件，在专家长期记忆后端选择它并填写服务地址和用户 Key | 新增的是插件源码，需构建并安装；服务端需另配向量和记忆抽取模型。健康检查通过不等于记忆提取已经可用；没有持久化重试队列 |
| Shell 可选内存保护 | 监测命令及其子进程的内存，超限时终止，降低脚本耗尽机器资源的概率 | 在运行环境设置 `QWENPAW_SHELL_MEMORY_LIMIT_MB`：`0` 关闭、`auto` 自动、正整数为 MiB 上限；批处理与资料转换场景可按机器资源设置 | 默认关闭；实际内存上限会取请求值与当前可用内存一半的较小值，`auto` 的请求值为 4 GiB；采样监测并非操作系统级硬配额，监测不可用时会记录提示并继续执行。数值模拟应考虑真实求解器的正常内存需求 |
| 更稳健的长对话与 Scroll | 改进 token 估算、溢出后的有界恢复，支持慢速摘要模型；完成的历史迁移不再反复扫描，备份使用实时 SQLite 快照 | 多轮科研协作、长文书任务可减少上下文超限中断；必要时调整 `scroll_config.summary_timeout_seconds`，默认 300 秒 | 保留本产品历史默认永久保存（0 天）；只有显式正数才启用保留期清理。压缩、恢复及备份不等于模型永不失败 |

| 更完整的插件更新识别 | 安装时记录市场来源身份，避免作者显示名不同导致“全部更新”漏掉第三方插件；依赖失败给出更清楚的诊断 | 已从上游市场安装的插件可以更可靠地关联更新目录，减少逐个检查；UGSci 应用继续沿用原签名组件或受校验替换 | 不会替用户自动安装或发布插件；已有缺少来源记录的旧安装不保证能反推原始来源 |
| 设置搜索、运行能力与插件主题扩展 | 搜索设置后定位对应控件；按实际运行后端显示可用设置；插件可注册搜索项、聊天插槽和主题令牌 | 更快找到专家、工具、安全与模型设置；后续 UGSci 扩展可通过公开接口接入，减少直接改宿主页面 | UGSci 相关设置继续统一在 `/settings/ugsci`；插件卸载必须清理注册项 |

此外合入 AnySearch 默认搜索提供方、Matrix 默认端到端加密依赖、钉钉长回复分段、Creator 2.0.4 媒体传输与连接探测加固、Windows 文本编辑 CRLF 保留、空媒体块过滤、自动记忆召回内部内容不泄露到频道，以及 code mode 工具参数与路由隔离等修复。

## 我们建议优先采用的顺序

1. 先使用通知、设置搜索、相对文件导航与长对话修复，改善现有日常工作流程。
2. 在一台测试机验证 Piccolo 与模型来源切换，再选择一个专家开启决策审批或完成自检，观察判断质量、延迟和内存占用。
3. 需要集中记忆服务时再试 OpenViking，先用合成信息验证跨会话召回与身份隔离，再决定哪些业务资料可以写入该服务。
4. 对批处理、转换脚本设置适合的 Shell 内存限制；数值模拟继续使用我们原有的运行监测、归档和结果校验。
